Bookmarks in mdterm - implementation design

Approach B: source-anchored marks. Signatures only - no bodies. Every name is a proposal; annotate anything you would call or split differently.

1Decision recap

The markdown renderer stamps each Line with the 1-based source line it came from, wrap_lines carries it through, and a new marks.rs turns "viewport top" into a Mark (source line + row + text fingerprint) and back, and owns persistence. viewer.rs only handles the two-key sequence and feedback.

  • Approach B - source-anchored marks (decided).
  • Mouse capture moves from m to M (decided).
  • Storage: one marks.toml in the platform state dir, keyed by canonical file path (decided).
  • README: fix the macOS config path while updating the controls tables (decided).
  • Review: marks are a-z only; line + text fingerprint with nearest-match re-anchoring; reusing a letter overwrites silently; missing paths pruned on every save. Names and splits approved.

2Structure overview

new modified existing, unchanged arrow = "depends on / calls"

Rule of the layering: the renderer records facts (source_line), marks.rs owns persistence and position mapping, viewer.rs owns keys, scrolling and toasts. marks.rs never touches ViewerState; it only sees &[Line] and &str.

3Units

marks.rs

NEWsrc/marks.rslayer: bookmarks (pure logic + persistence)

Owns bookmark persistence and the mapping between a layout position and a source-anchored Mark.

Collaborators: crate::style::Line (reads source_line), dirs, toml, serde. No dependency on the viewer.

  • MarkStore::load() - store backed by marks_path(); a missing or unreadable file yields an empty store (never fails).
  • MarkStore::load_from(path) - same with an explicit path; None gives a session-only store (tests, no state dir).
  • MarkStore::get(file, letter) - in-memory lookup; returns None if unset.
  • MarkStore::set(file, letter, mark) - updates memory first, then re-reads the file, merges, prunes paths that no longer exist, and writes atomically (tmp + rename). Returns MarkStoreError if it could not persist; the mark still works this session.
  • anchor_at(wrapped, top, source) - builds the mark for the viewport top; None if no line in the layout has a source line (empty doc, JSON).
  • resolve(mark, wrapped, source) - where the mark lands now; re-anchors by text after edits; None only if the layout is empty.

style.rs

MODIFIEDsrc/style.rslayer: rendering data types

Line gains its source position, and wrapping preserves it.

  • Line.source_line - new field, 1-based, None for content without markdown source.
  • Line::new(spans, meta) - new constructor; the ~50 Line { .. } literals in markdown.rs, json.rs, style.rs, viewer.rs move to it so future fields do not touch every site again.
  • wrap_lines - signature unchanged; every output line copies source_line from its input line in both the blockquote and plain branches (style.rs:111-141).

markdown.rs

MODIFIEDsrc/markdown.rslayer: rendering

Stamps the source line onto every line it emits, in one place: the into_offset_iter loop.

  • render_with - signature unchanged. Around each renderer.process(event, range) it records lines.len() before, then stamps the new lines with SourceLines::line_of(range.start). Lines pushed on a block's End event get the block's start line. The final flush_line is stamped with the last source line.
  • Renderer itself is untouched.

viewer.rs

MODIFIEDsrc/viewer.rslayer: interactive TUI

Handles the m/' + letter sequence and turns mark results into scrolling and toasts.

Collaborators: MarkStore injected through ViewerOptions, marks::anchor_at, marks::resolve.

  • ViewerOptions.marks / ViewerState.marks - injected store; ViewerState.pending_mark - the half-typed sequence.
  • markable_file() - canonical path of the current file; None for stdin or JSON.
  • top_line() - offset, or the current slide's first line in slide mode.
  • scroll_to_line(idx) - offset = idx.min(max_offset()), or selects the slide containing idx.
  • set_mark(letter) / jump_to_mark(letter) - the two actions; feedback via set_toast, no return value.
  • handle_mark_key - completes a sequence; a lowercase a-z dispatches; anything else, including uppercase, cancels silently.
  • Changed: handle_event consumes pending_mark right after the Ctrl+C check and before is_help_toggle (viewer.rs:996-1015), so m h sets mark h. handle_normal: m/' start a sequence, mouse capture moves to M (viewer.rs:1647). handle_slide_keys gets the same two bindings. finalize_layout copies source_line to expanded image rows (viewer.rs:638-647). render_status_bar shows m█ / '█ while pending, like the search prompt (viewer.rs:2819). help_sections gets the new entries.

main.rs

MODIFIEDsrc/main.rslayer: entry

Loads the mark store and injects it into the viewer.

json.rs

MODIFIEDsrc/json.rslayer: rendering

Mechanical: its 20 Line { .. } literals become Line::new(..); lines keep source_line: None. No behaviour change.

README.md, CLAUDE.md

MODIFIEDdocs

README: m/' and M in the controls tables, a short "Bookmarks" note with the marks file location, and the config path corrected for macOS (dirs::config_dir() is ~/Library/Application Support there, not ~/.config). CLAUDE.md: "Ten source files" becomes eleven, with a marks.rs entry.

5Call chains

call return error path

5.1 Startup and render: source lines get stamped

  1. main -> MarkStore::load(): MarkStore (calls marks_path(): Option<PathBuf>, then MarkStore::load_from(path))
  2. MarkStore::load_from -> read_marks_file(&path): Result<MarksFile, MarkStoreError> - any Err becomes an empty in-memory store
  3. main -> viewer::run(ViewerOptions { marks, .. }): io::Result<()> → ViewerState::new(opts, cols, rows) moves the store into state
  4. ViewerState::rebuild -> markdown::render_with(&content, cw, &theme, line_numbers, &syntect_res): (Vec<Line>, DocumentInfo)
  5. render_with -> stamp_source_line(&mut lines[before..], source_lines.line_of(range.start)) per parser event
  6. ViewerState::rebuild -> wrap_lines(&lines, cw): Vec<Line> - wrapped rows inherit source_line
  7. ViewerState::rebuild -> finalize_layout() - expanded image rows copy the placeholder's source_line
Error paths
  • No state dir: marks_path() is None → session-only store. User sees nothing until a set, which toasts "not saved".
  • Unreadable / corrupt / newer-version file → empty store, file left untouched. The error reappears on the next set (it re-reads), which refuses to write.

5.2 m + letter: set a mark

  1. handle_event -> handle_normal(state, Char('m'), mods): bool - sets state.pending_mark = Some(PendingMark::Set); status bar shows m█
  2. Next key: handle_event -> handle_mark_key(state, PendingMark::Set, Char('a')) - pending_mark.take() runs before is_help_toggle
  3. handle_mark_key -> ViewerState::set_mark('a')
  4. set_mark -> ViewerState::markable_file(): Option<PathBuf>
  5. set_mark -> marks::anchor_at(&self.wrapped, self.top_line(), &self.content): Option<Mark>
  6. set_mark -> MarkStore::set(&file, 'a', mark): Result<(), MarkStoreError>
  7. MarkStore::set -> read_marks_file(&path), merge entry, drop missing paths, write_marks_file(&path, &data) (tmp + rename): Ok(())
  8. set_mark -> set_toast("Mark 'a' set")
Error paths
  • Step 2, any key other than a-z (incl. uppercase, Esc, ?): sequence cancelled, key swallowed, no toast. Ctrl+C still quits (checked first).
  • Step 4 None (stdin or JSON) → toast "Marks need a markdown file".
  • Step 5 None (empty document) → toast "Nothing to mark here".
  • Step 6/7 Err(e) → mark is already in memory and works this session; toast "Mark 'a' set - not saved: {e}". Corrupt and NewerVersion never write, so the file is not clobbered.

5.3 ' + letter: jump to a mark

  1. handle_event -> handle_normal(state, Char('\''), mods): bool - pending_mark = Some(PendingMark::Jump); status bar shows '█
  2. Next key: handle_event -> handle_mark_key(state, PendingMark::Jump, Char('a'))
  3. handle_mark_key -> ViewerState::jump_to_mark('a')
  4. jump_to_mark -> ViewerState::markable_file(): Option<PathBuf>
  5. jump_to_mark -> MarkStore::get(&file, 'a'): Option<&Mark>
  6. jump_to_mark -> marks::resolve(&mark, &self.wrapped, &self.content): Option<MarkTarget> (internally relocate(&mark, source): (usize, bool), then first wrapped row with that source line + row, clamped to the block)
  7. jump_to_mark -> self.nav_history.push((self.current_file_idx, self.offset))
  8. jump_to_mark -> ViewerState::scroll_to_line(target.line_idx)
  9. jump_to_mark -> set_toast("Mark 'a'")
Error paths
  • Step 4 None → toast "Marks need a markdown file".
  • Step 5 None → toast "Mark 'a' not set"; no scroll.
  • Step 6 None (empty layout) → toast "Mark 'a' not set".
  • Step 6 MarkTarget { exact: false } - the fingerprint text was not found anywhere → jump to the stored line number anyway, toast "Mark 'a' - text changed, jumped to line N". Jumping never writes the file.

Deviations. (1) MarkStoreError is the first custom error enum - elsewhere mdterm uses io::Result or silent fallback; here the viewer must tell "no state dir", "corrupt", "newer version" and "I/O" apart to explain why a mark was not saved. (2) marks.rs is the first module that writes state to disk, so atomic write (tmp + rename) is new. (3) state_dir instead of config_dir: marks are machine state, not user configuration. (4) Line::new replaces struct literals - a one-time churn to avoid touching ~50 sites for every future field.

8Assumptions

Cheap to change later. Annotate any you disagree with.

  1. A mark is the top line of the viewport; jumping puts it back at the top (mdterm has no cursor).
  2. Jumping pushes onto nav_history, so Backspace returns to where you were.
  3. After m/', any key other than a-z cancels silently and is swallowed; the pending key shows in the status bar.
  4. Marks are unavailable for stdin and JSON (toast "Marks need a markdown file").
  5. Slide mode supports marks: set uses the slide's first line, jump selects the slide containing the mark.
  6. The marks file is written on every set (re-read, merge, atomic replace); jumping never writes, even after re-anchoring.
  7. A corrupt or newer-version marks file is never overwritten; marks still work for the session and the toast says why they were not saved.
  8. The fingerprint is the trimmed source line, capped at 80 chars; re-anchoring searches the whole file for the nearest exact match.

9Review decisions

All open questions are resolved and folded into the design above.

  1. Letters: lowercase a-z only. Uppercase cancels the sequence like any other non-a-z key; no A-Z marks for now.
  2. Edits: Mark stores line + text fingerprint; resolve re-anchors to the nearest matching line.
  3. Reusing a letter: overwrite silently, toast "Mark 'a' set".
  4. Missing files: MarkStore::set prunes paths that no longer exist on every save.
  5. Names and splits: approved as proposed.
