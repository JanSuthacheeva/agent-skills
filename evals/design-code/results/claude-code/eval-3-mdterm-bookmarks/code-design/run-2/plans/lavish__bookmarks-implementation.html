mdterm bookmarks - implementation design

Signatures, data and call order for source-anchored marks. There are no method bodies. Every name here is a proposal.

1 Recap2 Structure3 Units4 Data5 Call chains6 Conventions7 Test seams8 Assumptions9 Open questions

1. Decision recap

The renderer stamps every Line with the source line of the markdown block it came from, and wrap_lines copies that stamp onto every wrapped row. A mark stores the source line, the row within that block, and the line's text. When you jump, the line is found again by its text and then mapped onto the current wrapped.

Decided in phase 2
ApproachA: source-anchored
Keysm+letter sets, '+letter jumps. The mouse-capture toggle moves from m to M.
Mark namesa-z only, per file. No uppercase or global marks for now.
StorageOne marks.json in dirs::data_dir()/mdterm/, keyed by canonical absolute path. It is not part of config.toml.
EditsThe mark is re-found by its stored line text. If the text is gone, it falls back to the stored line number.

dirs::data_dir() is ~/Library/Application Support/mdterm/ on macOS and ~/.local/share/mdterm/ on Linux. dirs::state_dir() returns None on macOS, so data_dir is the right call.

2. Structure overview

new modified existing, reused

ViewerState calls markdown::render_with from rebuild() (src/viewer.rs:548). Marks reach the renderer only through Line.source_line. marks.rs knows nothing about rendering, and the renderer knows nothing about marks.

3. Units

src/marks.rs

newlayer: persistence + domain (sibling of config.rs)deps: serde, serde_json, dirs, std::fs

Owns what a mark is and how marks for one document are read from and written to marks.json.

  • MarkStore::open() -> Self: points at dirs::data_dir()/mdterm/marks.json. The path is None when the platform has no data dir.
  • MarkStore::at(path: PathBuf) -> Self: points at an explicit file. This is the test seam.
  • MarkStore::load(&self, doc: &Path) -> FileMarks: returns the marks for the canonicalized doc. It returns an empty map when the file is missing, unreadable, corrupt, a newer version, or when there is no path. It never fails, the same way Config::load never fails.
  • MarkStore::save(&self, doc: &Path, marks: &FileMarks) -> io::Result<()>: re-reads the file, replaces only this document's entry (or removes it when empty), and writes atomically via tmp + rename. It returns Err(InvalidData) when the existing file is corrupt or a newer version, so other documents' marks are never overwritten. It returns Err(NotFound) when there is no path or doc cannot be canonicalized.
  • Mark::relocate(&self, source: &str) -> usize: returns the source line the mark belongs on now. If line still has the same trimmed text, it returns line. Otherwise it returns the nearest line with that text (on a tie, the one above). If the text is gone or empty, it returns line, clamped to the last line.
  • is_mark_name(c: char) -> bool: returns true for 'a'..='z'.

src/style.rs

modifiedlayer: shared data types

Line records which source line it came from, and wrapping keeps that record on every row.

  • Line.source_line: Option<usize>: new field, the 0-based source line of the markdown block. It is None for JSON views and for lines built outside the markdown renderer.
  • wrap_lines(lines: &[Line], width: usize) -> Vec<Line>: the signature is unchanged. Every row produced from a line now inherits source_line, on all three branches. This is unlike meta, which only propagates to the first row for most types.
  • Existing Line { spans, meta } literals (about 50 across json.rs, markdown.rs, style.rs and viewer.rs) gain ..Default::default(). Line::empty() sets source_line: None.

src/markdown.rs

modifiedlayer: rendering

Stamps each emitted line with the source line of the event that produced it, in one place: the into_offset_iter loop.

  • Renderer.line_starts: Vec<usize>: new field, the byte offset of each source line, built once in Renderer::new.
  • Renderer::stamp_source_lines(&mut self, from: usize, byte_offset: usize): sets source_line on self.lines[from..] that are still None. Returns nothing.
  • source_line_at(line_starts: &[usize], byte_offset: usize) -> usize: binary-searches the 0-based line that contains byte_offset.
  • render_with(..): the signature is unchanged. The loop records lines.len() before each process and stamps afterwards, and the final flush_line() is stamped with the last event's offset. End events carry the whole block's range, so a block's lines get the block's first source line.

src/viewer.rs

modifiedlayer: TUI state + inputcollaborators: MarkStore, Mark, set_toast, nav_history

Turns the m/' key sequences into mark operations on the current document.

  • ViewerOptions.mark_store: MarkStore: injected from main, the same way theme and line_numbers are.
  • ViewMode::MarkSet, ViewMode::MarkJump: the modes that wait for the letter after m or '. accepts_text_input() includes them, so ? is taken as the mark key and does not open help. Its doc comment is updated to say "or waiting for a key argument".
  • ViewerState.mark_store: MarkStore, ViewerState.marks: FileMarks: the store and the current document's marks.
  • ViewerState::load_marks(&mut self): replaces self.marks with mark_store.load(path), or with an empty map for stdin. Called from new and switch_file.
  • ViewerState::current_path(&self) -> Option<&Path>: files[current_file_idx], or None for stdin.
  • ViewerState::mark_at_offset(&self) -> Option<Mark>: builds a Mark from the top visible row. It returns None when that row has no source_line.
  • ViewerState::set_mark(&mut self, name: char): stores the mark, persists it when there is a path, and shows a toast.
  • ViewerState::jump_to_mark(&mut self, name: char): relocates the mark, pushes the current position onto nav_history, scrolls, and shows a toast.
  • ViewerState::wrapped_idx_for_source(&self, line: usize, row: usize) -> usize: finds the block with the greatest source_line <= line and returns its first row plus row, clamped to the block's last row.
  • handle_mark_key(state: &mut ViewerState, code: KeyCode): always returns to Normal, then sets or jumps for a-z, does nothing for Esc, and shows the toast "Marks are a-z" for anything else.
  • Changed: handle_normal (m enters MarkSet, ' enters MarkJump, the mouse toggle moves to M), handle_event (dispatches both mark modes), switch_file (calls load_marks), finalize_layout (rebuilt image rows keep their placeholder's source_line), render_status_bar (shows a m█ / '█ prompt, like the search prompt), render_frame (images stay visible in mark modes), help_sections (new mark entries; Backspace becomes "Go back (after a link or mark jump)").

src/main.rs

modifiedlayer: entry point

Declares mod marks; and passes marks::MarkStore::open() into ViewerOptions. The export and piped paths never touch marks.

README.md

modifieddocs

Navigation table: add m+a-z and '+a-z. Features table: add M for mouse capture. The README never documented the old m binding, so this also fills that gap. Add a short note on where marks.json lives, next to the config file section.

Line.source_line

Option<usize>. It is Some for every line the markdown renderer emits, including spacer and rule lines, which take the line of the event that pushed them. It is None for JSON output. This is the only change to the rendering data model.

5. Call chains

Blue arrows are calls, grey dashed arrows are returns, and red dotted arrows are error paths.

5.1 Set a mark: m then a

  1. handle_event -> handle_normal(state, KeyCode::Char('m'), mods): bool
  2. handle_normal sets state.mode = ViewMode::MarkSet. render_status_bar shows the m█ prompt.
  3. handle_event -> handle_mark_key(state, KeyCode::Char('a'))
  4. handle_mark_key sets state.mode = ViewMode::Normal, checks is_mark_name('a'): true, and calls ViewerState::set_mark('a')
  5. ViewerState::set_mark -> ViewerState::mark_at_offset(): Option<Mark>. This reads wrapped[offset].source_line, counts the rows back to the block's first row, and reads the trimmed content line.
  6. ViewerState::set_mark -> FileMarks::insert('a', mark)
  7. ViewerState::set_mark -> ViewerState::current_path(): Option<&Path>. For Some(path): MarkStore::save(path, &marks): io::Result<()>
  8. MarkStore::save reads marks.json, replaces this document's entry, writes marks.json.tmp, and renames it over marks.json.
  9. ViewerState::set_mark -> ViewerState::set_toast("Mark 'a' set")
Error paths
  • Key is not a-z (for example A or 1): handle_mark_key shows the toast "Marks are a-z". Esc cancels with no toast. In both cases the mode is back to Normal.
  • No source line on the top row (JSON view): mark_at_offset returns None, and set_mark shows "Marks unavailable in this view". Nothing is stored.
  • save fails (the data dir is unwritable, marks.json is corrupt or a newer version, or the path cannot be canonicalized): io::Error is returned to set_mark, which keeps the mark in memory and shows "Mark 'a' set, not saved: {e}". The mark still works for this session.
  • stdin: current_path returns None, so save is skipped. The toast is "Mark 'a' set" and the mark lasts for the session only.

5.2 Jump to a mark: ' then a

  1. handle_event -> handle_normal(state, KeyCode::Char('\''), mods): bool. This sets state.mode = ViewMode::MarkJump and shows the '█ prompt.
  2. handle_event -> handle_mark_key(state, KeyCode::Char('a')), which sets mode = Normal and calls ViewerState::jump_to_mark('a')
  3. ViewerState::jump_to_mark -> FileMarks::get(&'a'): Option<&Mark>
  4. ViewerState::jump_to_mark -> Mark::relocate(&self.content): usize
  5. ViewerState::jump_to_mark -> ViewerState::wrapped_idx_for_source(line, mark.row): usize
  6. ViewerState::jump_to_mark pushes (current_file_idx, offset) onto nav_history, then sets offset = idx.min(max_offset())
  7. ViewerState::jump_to_mark -> ViewerState::set_toast("Jumped to mark 'a'")
Error paths
  • Mark not set: the toast is "Mark 'a' not set" and the offset is unchanged.
  • Marked text deleted from the file: relocate falls back to the stored line, clamped to EOF. It does not fail.
  • Document has no stamped rows (JSON): set_mark can never have stored a mark for it, so this path is unreachable. wrapped_idx_for_source returns 0 to be safe.

5.3 Load marks: startup and file switch

  1. main -> marks::MarkStore::open(): MarkStore, passed as ViewerOptions.mark_store
  2. viewer::run -> ViewerState::new(opts, cols, rows) -> ViewerState::load_marks()
  3. ViewerState::load_marks -> ViewerState::current_path(): Option<&Path>. For None (stdin): marks = FileMarks::new()
  4. ViewerState::load_marks -> MarkStore::load(path): FileMarks
  5. On a file switch (Tab, Shift+Tab, a local link, Backspace): ViewerState::switch_file(idx) -> ViewerState::load_marks(), after rebuild()
Error paths
  • marks.json missing, unreadable, corrupt or a newer version: load returns an empty map and shows nothing, the same as Config::load. The user only finds out on the next save, through the "not saved" toast, so the file is never clobbered without a word.
  • No data dir on the platform: the store's path is None, load returns an empty map, and save returns NotFound.

5.4 Rendering: how source_line gets onto wrapped rows

  1. ViewerState::rebuild -> markdown::render_with(content, cw, theme, line_numbers, syntect_res): (Vec<Line>, DocumentInfo)
  2. render_with -> Renderer::new(..), which builds line_starts
  3. For each (event, range): from = renderer.lines.len(), then Renderer::process(event, range.clone()), then Renderer::stamp_source_lines(from, range.start)
  4. Renderer::stamp_source_lines -> source_line_at(&self.line_starts, byte_offset): usize
  5. render_with -> Renderer::flush_line(), then Renderer::stamp_source_lines(from, last_start)
  6. ViewerState::rebuild -> style::wrap_lines(&lines, cw): Vec<Line>, where every row inherits source_line
  7. ViewerState::rebuild -> ViewerState::finalize_layout(), where rebuilt image rows copy the placeholder's source_line
Error paths
  • None. Stamping is total: a byte offset past EOF maps to the last line. JSON rendering (json::render_interactive and json::render_diagram) leaves source_line as None.

Deviations

  • mdterm has never written app state to disk before. save uses tmp + rename, which the codebase has no precedent for. A partially written marks.json would lose every document's marks, which is why.
  • ViewerOptions carries a service object (MarkStore) for the first time; until now it only carried values. This is what lets tests point the store at a temp file instead of the real data dir.
  • accepts_text_input() now also covers modes that wait for a single key argument. The name stays and the doc comment is widened, rather than adding a second predicate that is_help_toggle would also have to check.

8. Assumptions

  1. "Current position" means the top visible row (state.offset), the same position that [/] and nav_history use.
  2. Slide mode has no marks, because handle_slide_keys keeps owning every key there. In JSON views, m shows "Marks unavailable in this view".
  3. Marks on stdin input last for the session only and are never written.
  4. Setting a letter that is already used overwrites it without asking. There is no delete command or marks list in this iteration.
  5. Precision is per block plus a row offset. After a resize, a mark inside a long wrapped paragraph lands on the same block, with the row clamped to the block's length.
  6. Relocation happens only at jump time. The stored line is not rewritten when the text has moved.
  7. Two mdterm instances do not lock: each save re-reads and merges, and the last writer wins only for the same document.
  8. On-disk line numbers are 0-based. Toasts do not show line numbers.

9. Open questions

None. The design is approved. The Backspace question was answered in review, and the answer is folded into the design: a mark jump pushes (current_file_idx, offset) onto nav_history, so Backspace returns to where you were. There is no vim-style ''. The help and README text for Backspace becomes "Go back (after a link or mark jump)".
