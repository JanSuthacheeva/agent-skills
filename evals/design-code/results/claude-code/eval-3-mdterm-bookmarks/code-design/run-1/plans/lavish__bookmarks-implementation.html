Bookmarks: source-anchored marks

1. Decision recap

Every rendered Line records the 1-based source line it came from. A new marks.rs stores, per file, a-z marks as source line + line text in one JSON file. On jump, the text re-finds the line if the file was edited, and the source line maps back to whatever wrapped line it currently renders as.

Approach C - source-anchored Mouse capture moves m -> M Store: platform state dir / mdterm / marks.json Only lowercase a-z, per file No uppercase marks, no ''

2. Structure overview

newmodifiedexisting

Arrows read "depends on / feeds". The render pipeline only gains a field; all bookmark logic sits in marks.rs (pure + disk) and viewer.rs (keys + mapping to the wrapped view).

3. Units

marks.rs

newpersistencesrc/marks.rs

Responsibility: load, save and re-locate a file's bookmarks.

Collaborators: dirs, serde/serde_json, std::fs. Knows nothing about the viewer or wrapped lines.

  • Mark::capture - returns the mark for an existing line, or None past EOF.
  • Mark::resolve - never fails. It returns the current 1-based line, and the variant says how confident the match is.
  • FileMarks::load - silent fallback to empty, mirroring Config::load.
  • FileMarks::save - Err when there is no state dir, the path can't be canonicalized, the store is corrupt, or I/O fails. It reads the store again before writing, so a second mdterm instance doesn't clobber other files' marks.
  • load_from/save_to - take the store path explicitly, so tests can use a temp dir.

style.rs - Line, wrap_lines

modifieddata typessrc/style.rs

Responsibility: carry a rendered line's source line through wrapping.

Changes to existing code: about 13 Line { .. } literals here, 15 in markdown.rs, 20 in json.rs and 3 in viewer.rs gain ..Default::default(). That's the same idiom Style literals already use. Line::empty() sets None.

markdown.rs - Renderer

modifiedrender pipelinesrc/markdown.rs

Responsibility (added): stamp each emitted Line with its source line.

Three stamping rules, from most to least precise. Code rows get their own line. Flushed text lines get the line of their first text. Anything else (rules, tables, blank lines, decorations) falls back to the line where the event that produced it starts. render/render_with signatures are unchanged.

viewer.rs

modifiedTUIsrc/viewer.rs

Responsibility (added): turn m/'+letter into set/jump against the current file's marks.

Collaborators: crate::marks::{FileMarks, Mark, Resolution}, existing set_toast, max_offset, wrapped.

Changes to existing members

  • ViewerState::new - initialises marks via FileMarks::load when files is non-empty, otherwise FileMarks::default().
  • switch_file - reloads marks for the new path, next to the existing search.clear().
  • handle_normal - m enters Mark(Set) and ' enters Mark(Jump). The mouse-capture arm moves unchanged to M.
  • handle_event - new arm ViewMode::Mark(action) => { state.dirty = true; handle_mark(state, ke.code, action); }.
  • finalize_layout - rebuilt image rows copy source_line from the placeholder row.
  • render_status_bar - shows a pending hint ( m_ / '_ ) in the slot the search prompt uses.
  • render_frame - suppress_images also lets Mark(_) through, so images don't blink while a prefix is pending.
  • help_sections - Navigation gets ("m a-z", "Set mark") and ("' a-z", "Jump to mark"). Actions changes "m" to "M".
  • tests::ALL_MODES - adds both Mark variants.

main.rs, json.rs, README.md, CLAUDE.md

modified
  • src/main.rs - mod marks; (alphabetical, between markdown and style).
  • src/json.rs - Line literals gain ..Default::default(). No behaviour change: JSON lines have no source line, so marks are unavailable there.
  • README.md - key list: marks, and M for mouse capture. CLAUDE.md - eleven source files, with marks.rs described.

5. Call chains

5.1 Render stamps source lines (every rebuild)

  1. ViewerState::rebuild -> markdown::render_with(&content, cw, &theme, line_numbers, &syntect_res): (Vec<Line>, DocumentInfo)
  2. render_with -> Parser::into_offset_iter(): (Event, Range<usize>) per event
  3. render_with -> Renderer::process(event, range) - records event_start; push_span sets span_source_line; flush_line_with_meta / emit_code_block stamp lines
  4. render_with -> Renderer::stamp_unstamped(lines_before) - fallback for lines pushed directly
  5. ViewerState::rebuild -> style::wrap_lines(&lines, cw): Vec<Line> - pieces inherit source_line
  6. ViewerState::rebuild -> ViewerState::finalize_layout() - image rows keep source_line
  7. JSON files: json::render_* return lines with source_line = None. Nothing fails here; set_mark reports it later.

5.2 m then a - set a mark

  1. handle_event -> handle_normal(state, Char('m'), mods): bool - sets state.mode = ViewMode::Mark(MarkAction::Set); status bar shows " m_ "
  2. handle_event(Char('a')) -> handle_mark(state, Char('a'), MarkAction::Set) - mode back to Normal
  3. handle_mark -> ViewerState::set_mark('a')
  4. set_mark -> ViewerState::source_line_at_offset(): Option<usize>
  5. set_mark -> Mark::capture(&content, line): Option<Mark>
  6. set_mark -> FileMarks::set('a', mark)
  7. set_mark -> ViewerState::current_file_path(): Option<&Path>
  8. set_mark -> FileMarks::save(path): io::Result<()> -> read_mark_file -> write_mark_file (tmp + rename)
  9. set_mark -> ViewerState::set_toast("Mark a set")
  10. Key is not a-z (Esc, digit, arrow): handle_mark just returns to Normal, no toast. Uppercase A-Z: toast "Marks are a-z".
  11. source_line_at_offset or capture returns None (JSON view, empty document): toast "Nothing to mark here", nothing stored.
  12. current_file_path is None (stdin): the mark is kept in memory only, toast "Mark a set".
  13. save returns Err (no state dir, corrupt store, I/O): the mark stays in memory for this session, toast "Mark a set (not saved: <reason>)". A corrupt marks.json is never overwritten.

5.3 ' then a - jump to a mark

  1. handle_event -> handle_normal(state, Char('\''), mods): bool - sets state.mode = ViewMode::Mark(MarkAction::Jump); status bar shows " '_ "
  2. handle_event(Char('a')) -> handle_mark(state, Char('a'), MarkAction::Jump) - mode back to Normal
  3. handle_mark -> ViewerState::jump_to_mark('a')
  4. jump_to_mark -> FileMarks::get('a'): Option<&Mark>
  5. jump_to_mark -> Mark::resolve(&content): Resolution
  6. jump_to_mark -> ViewerState::line_idx_for_source(line): Option<usize>
  7. jump_to_mark sets state.offset = idx.min(state.max_offset())
  8. On Resolution::Moved(line): jump_to_mark -> FileMarks::set('a', Mark { line, text }) -> FileMarks::save(path) (heal; save error ignored)
  9. get returns None: toast "Mark a not set".
  10. Resolution::Approximate(line): still jumps, toast "Mark a: text changed, jumped to line N".
  11. line_idx_for_source returns None (no stamped lines, e.g. the file became invalid JSON or empty): toast "Mark a not found", offset unchanged.

5.4 Open or switch file - load marks

  1. viewer::run -> ViewerState::new(opts, cols, rows) / handle_normal(Tab) -> ViewerState::switch_file(idx): bool
  2. -> ViewerState::current_file_path(): Option<&Path>
  3. -> FileMarks::load(path): FileMarks -> store_path() -> store_key(path) -> read_mark_file(store)
  4. state.marks = loaded (or FileMarks::default() for stdin)
  5. No state dir, missing/corrupt marks.json, or canonicalize fails: load returns empty FileMarks silently, like Config::load. A corrupt store surfaces on the next save as "not saved".

7. Test seams

  • marks.rs (unit): capture/resolve on string fixtures (exact, moved up/down, nearest of duplicates, approximate clamp). load_from/save_to against a temp dir: round-trip, preserves other files, refuses to overwrite corrupt JSON, ignores non a-z keys.
  • markdown.rs (unit): render of a fixture with heading, wrapped paragraph, list, fenced code, table. Assert each line's source_line.
  • style.rs (unit): wrap_lines copies source_line to every wrapped piece, including blockquote wraps.
  • viewer.rs (unit): extend make_state_with_lines (viewer.rs:4249). Cover line_idx_for_source, source_line_at_offset, and handle_mark transitions (letter / Esc / uppercase). For set_mark/jump_to_mark use stdin state, so nothing touches disk. Add the Mark modes to the is_help_toggle matrix and check help has no duplicate keys.
  • E2E (manual, real TTY): cargo run -- test.md, ma, resize, 'a; quit and reopen; then insert lines above in an editor while auto-reload runs.

8. Assumptions

  1. "Current position" means the top line of the viewport. Jumping puts the marked line at the top.
  2. Setting an existing letter overwrites it silently, like vim.
  3. An exact jump shows no toast, because the scroll is the feedback. Only failures and approximate jumps toast.
  4. A mark found on a different line after an edit is healed: its stored line is updated on jump.
  5. Jumps don't push onto nav_history, so Backspace stays "back after link".
  6. Marks are inactive in slide mode (slide keys are handled before handle_normal) and in JSON views (no source lines).
  7. Precision is one rendered block: a mark inside a long wrapped paragraph lands on the paragraph's first line. Code blocks are exact per line.
  8. Entries for deleted files are never pruned. The file grows by a few bytes per marked document.

9. Decisions made in review

  • Store location: dirs::state_dir(), falling back to dirs::data_dir() where there is no state dir. That gives ~/.local/state/mdterm/marks.json on Linux, ~/Library/Application Support/mdterm/marks.json on macOS and %APPDATA%\mdterm\marks.json on Windows.
  • File identity: marks are keyed by canonical absolute path. Renaming or moving a file loses its marks, and that's accepted.
  • Assumptions 1-8: all confirmed.
