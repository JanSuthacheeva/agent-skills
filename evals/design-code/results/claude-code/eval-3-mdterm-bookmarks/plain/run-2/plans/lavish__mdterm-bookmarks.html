# Bookmarks for mdterm

Vim-style marks: m+letter sets a mark, '+letter jumps to it, and marks persist per file across sessions. The hard part is the anchor. "Position" today is a wrapped-line index, and that index changes whenever the terminal is resized, an image loads, or the file is edited.

ma-zset mark at top of viewport
'a-zjump to mark
Backspaceback to where you jumped from
Mmouse capture (moved from m)

## What the code does today

conflict

m is taken

m toggles mouse capture (viewer.rs:1647, help at :3637). ' and M are unbound.

unstable

offset is not a position

state.offset indexes wrapped, so it changes on resize, image load (finalize_layout), line-number toggle, auto-reload, and next session's width.

gap

lines forget their source

Line is { spans, meta }. The renderer gets byte ranges from into_offset_iter() (markdown.rs:1585) and throws them away.

ordering

keys get grabbed first

is_help_toggle takes h/? before mode dispatch, and slide and JSON handlers take h l j k H L D. The prefix has to win before all of them.

reuse

back navigation exists

nav_history: Vec<(file_idx, offset)> plus Backspace. A jump pushes onto it for free.

reuse

serde_json is in

No new dependencies. dirs is already used for config.

## Architecture

## 1. Source anchors on rendered lines

style.rs

  • Add src: Option<usize> to Line (a byte offset into the markdown source).
  • wrap_lines already clones lines, so continuation rows inherit it.
  • finalize_layout copies it onto expanded image rows.

markdown.rs

  • Record line_src when the first span of a pending line is pushed, and set it in flush_line_with_meta.
  • Code blocks: exact offset per line (block start plus each \n). Tables: TableRow range. Lists: Item start.
  • Spacers, rules, JSON and diagrams get None.

## 2. src/marks.rs - pure logic, no TUI

anchor_at

Start at wrapped[offset] and walk forward to the first row with src. Convert the byte offset to a source line, and record that line's trimmed text as a fingerprint.

resolve - runs at jump time

  1. Source line a.line still reads a.text: use it.
  2. Otherwise, use the nearest line with equal text (covers lines inserted or deleted above the mark).
  3. Otherwise, clamp a.line to the end of the file.
  4. Map to the first wrapped row of the block containing that line, then clamp to max_offset().

## 4. Persistence

Location

  • dirs::state_dir(): Linux ~/.local/state/mdterm/marks.json
  • falls back to data_local_dir(): macOS ~/Library/Application Support/mdterm/marks.json
  • It's state, not config, so it stays out of config.toml.
  • Key: fs::canonicalize(path)

Writes

  • On every set: read-modify-write of only this file's entry.
  • Temp file in the same dir, then rename. Atomic, so a crash can't corrupt the store.
  • Concurrent instances don't overwrite each other's files.
  • Entries for deleted files are pruned on write.

Failure modes

  • Corrupt or unreadable store: empty marks, viewer keeps working.
  • Save error: toast Could not save marks.
  • stdin input: session-only marks.
  • JSON files: toast Marks are not supported for JSON.

## Risks

ux

Moving mouse capture from m to M breaks muscle memory for existing users. Call it out in the release notes.

precision

Inside a long wrapped paragraph, a jump lands on the paragraph's first row. Code blocks are exact per line.

collisions

Repeated identical lines (for example ---): the nearest match wins, which is the correct bias.

## Decisions

decided

Mouse capture moves to M

m is now the mark prefix, following the vim convention.

decided

Letters a-z only

A-Z stays free for possible future cross-file marks. After m or ', an uppercase letter cancels like any other non-mark key.

decided

JSON is out of v1

m and ' show the toast Marks are not supported for JSON.
