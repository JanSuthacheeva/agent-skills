mdterm / feature plan

# Vim-style marks

Set a mark with m+letter, jump back with '+letter. Marks are saved per file between sessions, and still land in the right place after a resize, a line-number toggle, image loading or an edit to the file.

m a-z

Set a mark at the top of the viewport (current slide in slide mode).

' a-z

Jump to a mark. Pushes the current position onto nav_history.

' '

Jump to the previous position. Pressing it again toggles back.

M

Mouse capture toggle, moved here from m.

8Marks for files that no longer exist are pruned on load.

## Why scroll offset can't be saved

state.offset is an index into wrapped, the lines after word wrapping. The same paragraph sits at a different index after any of these:

Resize / width

Event::Resize triggers rebuild(), which wraps again at the new content_width().

l line numbers

Adds a gutter, which narrows the text and changes wrapping (viewer.rs:1636).

Images load

finalize_layout grows the 3-row placeholders to their real height (viewer.rs:605).

The fix: the renderer already gets source byte ranges from parser.into_offset_iter() (markdown.rs:1585) and then discards them. Keep each line's source line number on Line and save marks in source coordinates.

## Architecture

Top row: the existing render pipeline, plus a source field. Bottom row: the new marks path. capture and resolve are pure functions over wrapped and the source text, so they are unit-testable without a terminal.

### 1. Source line tracking

style.rs

Add pub source: Option<usize> (0-based) to Line. word_wrap and the blockquote wrapping path copy it to every piece. Line::empty() sets it to None.

markdown.rs

Tagging happens in one place, in render_with: after each process(event, range), lines that are new and still untagged get line_of(range.start). Code block content lines are tagged exactly (text_start + i) by the code block renderer itself.

viewer.rs

finalize_layout copies source from each image placeholder to its expanded rows.

json.rs

All lines get source: None. JSON views have no stable source mapping, which is why marks are off there.

### 2. New module src/marks.rs

capture(wrapped, pos, source)

  1. Find the first wrapped line at or after pos with a source line. Search backward if there is none after.
  2. row = how many wrapped rows below the first row of that source line.
  3. text = that source line with trailing whitespace trimmed.

resolve(mark, wrapped, source)

  1. If mark.line still has text equal to mark.text, use it. Otherwise use the nearest line with that text (ties go up). Blank lines are never relocated. If no match, fall back to mark.line, clamped.
  2. Find the first wrapped line whose source is at or after the target. Add row, clamped to the rows that line spans.
  3. The caller clamps the result to max_offset.

Same width exact

Source line plus row gives back the same top line.

After resize same line

Lands on the first row of the same source line.

After edit follows text

Lines inserted above the mark: it finds its text again at the new line number.

### Storage

  • Path: dirs::state_dir() (Linux, ~/.local/state), falling back to dirs::data_dir() (macOS, ~/Library/Application Support), then mdterm/marks.json. Not config.toml: that file is for settings the user writes.
  • Keys: fs::canonicalize, so symlinks and relative paths share marks. BTreeMap keeps the output order stable.
  • Load: missing file means no marks. Entries for files that no longer exist are pruned. If the file can't be parsed, it is renamed to marks.json.bak and a toast reports it on startup.
  • Set: re-read the file from disk, which picks up marks from other running instances. Apply the change, prune, write a temp file in the same directory, then rename. If writing fails, the mark is kept for the session and the toast says it wasn't saved.
  • stdin: marks go in a session-only map and are never written.

### 3. Viewer integration

Keys are routed in this order. The pending check must come before is_help_toggle, otherwise m h would open help instead of setting mark h.

New state

marks: MarkStore, passed in through ViewerOptions (main.rs calls MarkStore::load(), tests use a tempdir). pending_mark: Option<MarkAction>, where MarkAction is Set or Jump.

New helpers

position() and jump_to_line(idx) handle both slide mode and normal mode. mark_file() returns the canonical path, or None for stdin. go_back(record_current) is shared by Backspace (false) and '' (true, so it toggles).

## Alternatives considered

Field on Line chosen

The source line travels through wrapping, image expansion and clones with no extra work. Cost: about 50 mechanical Line { .. } literal updates, all caught by the compiler.

Parallel Vec<usize> map rejected

Fewer edits up front, but every transform (wrap_lines, finalize_layout) has to keep a second vector in step. Easy to get wrong later.

Heading-anchored marks rejected

Heading text plus a delta. Survives edits, but is coarse between headings and fails in documents without headings.

One marks.json chosen

One file to read, prune and merge. Atomic rename, with the format readable by eye.

One file per document rejected

Hashed file names can't be inspected, and pruning means scanning a directory.

Inside config.toml rejected

Mixes state the app writes with settings the user writes. Rewriting the file would clobber the user's comments.

## Risks

Precision inside tables and long paragraphs

After a resize, the jump lands on the start of the block, not the exact row. With the same width it is exact.

Duplicate line text

Relocation picks the nearest match. After an edit, a mark on one of two identical rows can land on the other.

Concurrent instances

There is no file lock. Each write re-reads the file first, so the worst case is losing one mark when two instances set marks at the same moment.

Muscle memory for m

Pressing m now waits for a letter, and any other key cancels it, so nothing breaks. The help screen and README point to M.
