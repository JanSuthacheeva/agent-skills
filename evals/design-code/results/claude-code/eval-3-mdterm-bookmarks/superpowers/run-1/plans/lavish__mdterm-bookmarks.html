mdterm - design spec - 2026-10-01

Bookmarks: m + letter, ' + letter

Vim-style marks that stay on the same content through edits, resizes and restarts. Each mark is tied to a line in the source file, not to a scroll offset, and saved per file in the platform state directory.

1Goal and decisions

Set

Sets a mark at the top line of the viewport.

Jump

Survives edits (including auto-reload), resizes and the line-number toggle.

2Current state (verified in code)

offset can't be persisted

state.offset indexes wrapped rows. It shifts on resize, l, image expansion in finalize_layout, and every edit.

No source position on Line

Line has only spans and meta, although render_with already iterates into_offset_iter() (markdown.rs:1585).

Help toggle runs first

handle_event checks is_help_toggle (viewer.rs:999) before handle_normal, so a pending mark must be handled before it, or mh opens help.

Early returns

handle_normal returns early for slide mode and interactive JSON (viewer.rs:1610-1617). The m/' check goes above them so the "unavailable" toast can show.

Toasts are always ✓

viewer.rs:3023 prefixes every toast with a check mark, including failures like "Invalid JSON". See 6.5.

m is undocumented

Mouse capture (viewer.rs:1647) is in the help overlay but not in the README key table (README.md:74-110).

4Source lines through rendering

src/style.rs - new field and constructor

All ~51 Line { .. } literals in markdown.rs, style.rs, json.rs and viewer.rs move to Line::new(..), so the field is set in one place. This is done as its own mechanical commit.

Stamping rules in markdown.rs (priority order)

The renderer builds a line-start index once and maps byte offsets to lines with binary search.

Rule 1

Span-buffer lines

When current_spans goes from empty to non-empty, record buffer_line from the current event. flush_line_with_meta stamps with it.

Needed because list items flush on the next Start(Item) (markdown.rs:1101).

Rule 2

Code rows

emit_code_block stamps fence_line + 1 + i per row, so marks inside long code blocks don't snap to the fence.

Rule 3

Everything else

render_with stamps rows still None after each process(event, range) with range.start's line: blanks, heading separators, rules, tables, images, diagrams.

Precision. Paragraphs and tables resolve to their first row. A mark inside a long paragraph lands at its start, at most a few rows off.

Propagation and lookups

  • wrap_lines copies source_line to every wrapped row, including blockquote rows. This differs on purpose from meta, which is propagated selectively.
  • finalize_layout gives expanded image rows the placeholder's source_line.
  • json.rs rows are always None.

5src/marks.rs

src/marks.rs - public surface

How resolve finds a mark after edits

capture trims the source line and truncates it to 80 characters on a char boundary. Candidates in resolve are normalized the same way.

Storage

Location

dirs::state_dir() or else dirs::data_local_dir(), then mdterm/marks.json.

  • macOS: ~/Library/Application Support/mdterm/marks.json
  • Linux: ~/.local/state/mdterm/marks.json

Write path in set

  1. Update memory.
  2. Re-read disk and merge only this (file, letter).
  3. create_dir_all, write marks.json.tmp, rename.

Two instances never erase each other's marks; for the same (file, letter) the last write wins. A crash can't leave a half-written file.

marks.json (pretty-printed, keyed by canonical path)

Error handling

SituationBehavior
No state or data dirpath = None, marks are session-only, set returns NoStateDir.
marks.json missingEmpty store; created on first set.
Unparsable (load, or re-read in set)Rename to marks.json.corrupt, start empty, notice "Marks file was unreadable, moved to marks.json.corrupt".
version > 1Read what parses, read_only = true. set updates memory and returns ReadOnly. Newer data is never overwritten.
Write or rename failsMemory already updated, set returns Io(err).
canonicalize failsUse the path as given.

No pruning of entries for missing files: entries are tiny, and pruning would erase marks on temporarily unmounted volumes.

6Viewer integration

State and construction

  • ViewerOptions gains marks: MarkStore. main.rs calls MarkStore::load(); tests pass MarkStore::at(tempdir) and never touch real user data.
  • ViewerState gains marks, pending: Option<PendingKey> (SetMark | JumpMark) and mark_file: Option<String> (canonical path, computed in new() and switch_file(), None for stdin).
  • On the first frame, marks.take_notice() is shown as a warning toast if present.

Key flow

Set - m{c}
  1. line = source_line_at(offset), anchor = Anchor::capture(&content, line)
  2. marks.set(file, c, anchor)
  3. Toast "Mark c set", or warning "Mark c set (not saved: {err})"
Jump - '{c}
  1. No anchor: warning "Mark c not set"
  2. resolved = anchor.resolve(&content), target = offset_for_source_line(resolved)
  3. If target != offset: push (current_file_idx, offset) to nav_history, set offset
  4. If resolved != anchor.line: save healed anchor (error ignored)
  5. No toast on success
Nothing to do for auto-reload, resize or the line-number toggle. Anchors are resolved against current content at jump time, and source_line survives every rebuild.

6.5 Toast kinds (small fix, needed by this feature)

8Testing

Anchor

  • trim and 80-char truncation without splitting multi-byte text
  • exact hit; shifted down and up; 200 lines inserted above
  • nearest of duplicates; equal-distance tie picks the earlier line
  • deleted line clamps; empty snippet; empty file

MarkStore (tempdir)

  • set then reload round-trips
  • two stores on one path keep each other's marks
  • no .tmp left; corrupt file moved aside with notice
  • version 2 is read-only and unchanged on disk; no path returns NoStateDir

Rendering

  • source_line for headings (and H1/H2 separators), paragraphs, every list item (lazy flush), task items, each code row, tables, blockquotes, images
  • wrap_lines copies to every row, including blockquotes

Viewer (make_state_with_lines)

  • ma, scroll, 'a restores
  • mh and '? don't open help; Esc cancels
  • jump pushes nav_history; Backspace returns
  • M toggles mouse; unavailable toasts for slide, JSON, stdin
  • same source line after width change and l

End-to-end in tmux (real binary, HOME set to a temp dir)

  1. cargo build; open a fixture with a long code block and several headings in a tmux pane.
  2. Scroll so a heading is on top, press m a, quit with q.
  3. Insert 30 lines at the top of the file. Reopen with a different --width.
  4. Press ' a; tmux capture-pane -p shows the heading on the top content row.
  5. With mdterm open, insert lines above the heading from another shell (auto-reload), press ' a, verify again.
  6. Inspect marks.json under the temp HOME: the healed line matches the new position.
