Bookmarks: per-file marks that survive resizes and edits

Vim-style marks for long Markdown documents you come back to. m + letter sets a mark at the top of the viewport, ' + letter jumps back, and marks are saved per file between sessions.

status: awaiting your review
Success criterion. Set a mark, quit, change the terminal width or insert text above the mark, reopen, press 'a, and the same passage is at the top of the viewport.

After the prefix key, the next key is always consumed. a-z runs the action, and anything else (including Esc) cancels silently.

Why the scroll offset can't be saved

Today

state.offset is an index into state.wrapped, the lines after word-wrapping. The same passage ends up at a different index whenever any of these change:

  • terminal width or the width config
  • the l line-numbers toggle
  • image row expansion in finalize_layout
  • any edit above the passage

Proposed

Each rendered Line carries the source line it came from. A mark stores the source line plus that line's text. Wrapped indices are computed only at jump time, against the current layout.

a = { line = 120, text = "## Persistence" }

Architecture

style.rs

src/style.rs:56
  • Add pub source_line: Option<usize> (1-based) to Line.
  • wrap_lines / word_wrap copy it to every wrapped piece. meta is only copied to the first piece for most types.
  • All ~47 Line { .. } literals get source_line: None. Image row expansion (viewer.rs:639) copies the image line's value.

markdown.rs

src/markdown.rs:1585
  • Build a line-start table once per render. Byte offset to line via partition_point.
  • Default stamping: after each process(event, range), any new line still at None gets the line of range.start. One place, no per-site changes.
  • Code blocks are emitted all at once: content line i gets fence_line + 1 + i.
  • Tables are buffered until End(Table): record the line at each Start(TableHead) / Start(TableRow) and stamp each row with it.

marks.rs (new)

src/marks.rs
  • No terminal or viewer code. Pure resolve plus MarkStore I/O.
  • Keys: fs::canonicalize(path), falling back to the path as given.
  • set re-reads the file, updates one entry, writes marks.toml.tmp and renames it. Safe after a crash and with several instances open.

viewer.rs

src/viewer.rs:1606 handle_normal
  • enum MarkOp { Set, Jump }, pending_mark: Option<MarkOp>, marks: MarkStore.
  • A one-key prefix, not a ViewMode. It's checked before the other Normal-mode keys, including before the slide-mode early return.
  • Set: first wrapped line at or after offset with a source_line.
  • Jump: resolve against state.content, push nav_history, clamp to max_offset.
  • File key: state.files[state.current_file_idx].

Resolving a mark at jump time

  1. Blank text: use mark.line clamped to the file. exact unless it was clamped.
  2. Same line, same text: use it. exact = true.
  3. Text found elsewhere: use the matching line closest to mark.line, the earlier one on a tie. exact = true, since it's the same passage, just moved.
  4. No match: mark.line clamped, exact = false, toast Mark 'a' moved - nearest position.

Precision is per rendered logical line: heading, paragraph, list item, code line, table row. A mark set in the middle of a paragraph lands on the paragraph's first line.

Error handling

Every failure is non-fatal: show a toast and keep viewing.

SituationBehavior
Marks file missingEmpty store. File and directories are created on the first save.
Marks file can't be parsedNever overwritten. Marks work for the session. Toast: marks.toml unreadable - marks not saved.
No data dir, or the write failsMark kept for the session. Toast: Could not save mark: <reason>.
canonicalize failsPath used as given.
'x with x unsetToast: Mark 'x' not set.
Stored line past end of fileClamped, exact = false, "moved" toast.
Stdin, JSON view, slide modeToast: Marks unavailable for stdin / in JSON view / in slide mode.
File auto-reloadsNothing to do: marks are resolved only at jump time.
Prefix, then a non-letter keyCancelled silently. The key is not processed further.

Risks

Line literal churn

The new field touches ~47 Line { .. } literals across four files. The changes are mechanical and the compiler catches any that are missed.

Mid-paragraph precision

Marks snap to the start of a paragraph. That's fine for the stated use, and per-span source offsets could refine it later.

Muscle memory

m no longer toggles mouse capture. The help overlay and README document the move to M.
