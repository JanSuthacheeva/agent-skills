Markdown renderer fills in source_line

feat(markdown): stamp source lines on rendered output
Files
  • src/markdown.rs (Renderer, flush_line_with_meta, emit_code_block, emit_table, process, render_with)
Approach
  • Line-start table: built once per render. line_of uses partition_point, clamped to the line count.
  • Default stamp: any new line still at None after each event gets that event's start line.
  • Buffered spans: current_src remembers where the pending spans started, so a paragraph flushed by a later event, such as a nested list starting, keeps its own line.
  • Code blocks: first_line + i. Tables: one line per row, recorded at Start(TableHead/TableRow).
Tests
  • source_line_headings_and_paragraphs
  • source_line_list_items
  • source_line_code_block_per_line
  • source_line_indented_code_block
  • source_line_table_rows
  • every_line_has_a_source_line
Core stamping code 
for (event, range) in parser.into_offset_iter() {
    let from = renderer.lines.len();
    let line = renderer.line_of(range.start);
    renderer.process(event, range);
    renderer.stamp_new_lines(from, line);
}

fn stamp_new_lines(&mut self, from: usize, line: usize) {
    for l in &mut self.lines[from..] {
        l.source_line.get_or_insert(line);
    }
    if self.current_src.is_none() && !self.current_spans.is_empty() {
        self.current_src = Some(line);
    }
}

jump_to_mark 
fn jump_to_mark(state: &mut ViewerState, letter: char) {
    let path = current_file_path(state);
    let Some(mark) = state.marks.get(&path, letter).cloned() else {
        state.set_toast(format!("Mark '{letter}' not set"));
        return;
    };
    let target = resolve(&mark, &state.content);
    let max = state.max_offset();
    let idx = state
        .wrapped
        .iter()
        .position(|l| l.source_line.is_some_and(|s| s >= target.line))
        .unwrap_or(max);
    state.nav_history.push((state.current_file_idx, state.offset));
    state.offset = idx.min(max);
    state.set_toast(if target.exact {
        format!("Jumped to '{letter}'")
    } else {
        format!("Mark '{letter}' moved - nearest position")
    });
}

Global constraints

Behavior

  • Letters a-z only, no Ctrl/Alt
  • Source lines are 1-based everywhere
  • Marks file in dirs::data_dir()/mdterm/
  • A file that can't be parsed is never overwritten
  • A jump pushes onto nav_history

Toast strings (verbatim)

  • Mark 'a' set / Jumped to 'a'
  • Mark 'a' moved - nearest position
  • Mark 'a' not set / Nothing to mark here
  • Marks unavailable for stdin / in JSON view / in slide mode
  • marks.toml unreadable - marks not saved
  • Could not save mark: <reason>

Differences from the spec

ItemNote
Nothing to mark hereNew toast for an empty document (focus 5). It follows the spec's rule that failures show a toast and don't crash.
On-disk layoutThe data is the spec's path -> letter -> {line, text}, but toml::to_string may write it as ["path".a] table headers rather than the spec's inline tables. Tests only check that marks survive a save and reload.
Merge after saveAfter a successful save, marks other mdterm windows wrote to disk are also loaded into memory.
