Bookmarks for mdterm

ma sets a mark, 'a jumps back to it. Marks are stored per file and survive restarts.

Approved: m used to toggle mouse capture (src/viewer.rs:1647). That toggle moves to M, so m/' work as they do in vim.

Current state (verified)

Key conflict

m toggles mouse capture, both in the handler and in the help entry. ' and M are not used by any handler, including slide and JSON.

Position depends on layout

offset is an index into wrapped, the list of lines after word-wrapping. It changes with terminal width, line numbers and image row expansion. Saving it to disk would be wrong.

Source info is thrown away

render_with already gets byte ranges from into_offset_iter(), but Line has no field to keep them.

Core decision: what a mark points to

rejected

Wrapped offset

Simple, but breaks on any resize, line-number toggle or image load.

rejected

Heading + distance

Coarse, fails in files without headings, and the distance is again measured in wrapped lines.

chosen

Source anchor

Source line number plus that line's trimmed text. Doesn't depend on layout, and survives edits above the mark.

How resolve finds the line

  1. If the text at the stored line still matches, use that line.
  2. If it doesn't, find the line with the same text that is nearest to the stored line number. This handles text added or removed above the mark.
  3. If no line matches, fall back to the stored line number, clamped to the end of the file.

The result is then mapped to the first wrapped line of the block that contains it, clamped to max_offset.

Architecture

style.rs + markdown.rs

Source mapping on Line

  • New field source: Option<usize> on Line. Every struct literal gets updated; JSON lines get None.
  • Wrapping copies source onto every continuation line, the same way meta is copied today.
  • Lines are stamped in one place, the render_with loop. Only lines that are still None and not blank get stamped.
  • Code blocks get an exact offset per line at their push site, so marks don't snap to the opening fence.
new marks.rs

Pure functions + store

  • anchor_at(content, byte) and resolve(content, &anchor) are pure functions that are easy to unit test.
  • MarkStore handles load and save, with at(path) for tests.
  • Files are keyed by canonical path, so ./a.md, a.md and symlinks share the same marks.
viewer.rs

Wiring

  • New state: pending_mark: Option<MarkAction>, marks and mark_store.
  • Marks load in new() and again in switch_file.
  • Each jump pushes the current position onto nav_history, so Backspace takes you back.
  • Helpers source_at_offset() and offset_for_source().

Stamping without touching every push site

for (event, range) in parser.into_offset_iter() {

Persistence

Location and format

dirs::state_dir().or_else(dirs::data_local_dir)/mdterm/marks.json

  • Linux: ~/.local/state/mdterm/marks.json
  • macOS: ~/Library/Application Support/mdterm/marks.json
  • Marks are state written by the program, not config, so they don't go in config.toml.
{ "version": 1,
  "files": {
    "/abs/notes.md": {
      "a": { "line": 42, "text": "## Install" } } } }

Write strategy

  • On every set: read from disk, replace only this file's entry, then write to a .tmp file and rename it into place. Two instances open on different files won't overwrite each other's marks, and a crash can't leave a half-written file.
  • On every save, entries for files that no longer exist are removed.
  • A corrupt file is renamed to marks.json.corrupt, the store starts empty, and a toast appears once.
  • Stdin has no path, so its marks last for the session only.
  • If the directory can't be written, marks still work for the session and a toast explains why they weren't saved.

Scope defaults (overridable)

  • Only a-z. A-Z stay free in case global marks across files (vim-style) are wanted later.
  • No ''. Backspace already returns to the previous position through nav_history.
  • No marks list overlay in v1. Setting a mark on a letter that is already used overwrites it silently, as in vim.
  • Docs: a new "Marks" section in help_sections(), updated README key table, and CLAUDE.md now lists 11 source files.

Tests

Unit

  • marks.rs: unchanged content, line inserted above, deleted line falls back to clamped number, nearest duplicate wins, store round-trip, saving keeps other files, corrupt file is backed up.
  • markdown.rs: headings, paragraphs and code-block lines get the expected offsets.
  • style.rs: wrapping copies source onto continuation lines.
  • viewer.rs: a mark set at 80 columns lands on the same heading after a rebuild at 40 columns with line numbers on; pending state cancels correctly; M toggles the mouse.

E2E (real binary in tmux)

  1. Set ma partway down test.md, then quit.
  2. Reopen in a narrower pane and press 'a. It should land on the same content.
  3. Insert lines above the mark in an editor, let auto-reload run, and press 'a. It should still find the content.
