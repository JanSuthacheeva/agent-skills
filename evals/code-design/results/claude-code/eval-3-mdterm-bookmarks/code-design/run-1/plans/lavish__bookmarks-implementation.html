mdterm bookmarks - implementation design

Approach C: a new marks.rs module, with each mark stored as a source line. Below are the signatures and call order only - no method bodies.

1. Decision recap

A mark stores the 0-based source line of the markdown at the top of the viewport. The line is stamped onto every Line by the renderer and copied through wrapping, so a mark points to the same text at any terminal width, theme or line-numbers setting. The new marks.rs module owns the mark types and the marks file. viewer.rs owns the two-key sequence and converts between scroll offset and source line.

Decided in round 1: approach C (source-line anchor, not wrapped offset or heading + delta). Mouse capture moves from m to M, and m becomes set-mark.

Decided in round 2: marks are a-z only, per file, and A-Z are reserved (treated as invalid). Marks must survive small edits made outside mdterm, so each Mark also stores a fingerprint of the marked source line's text. On jump, Mark::resolve looks for that text and re-anchors to the nearest matching line.

2. Structure overview

new modified existing, unchanged on disk / external

Arrows show "uses". Everything mark-related in the viewer stays in viewer.rs. marks.rs knows nothing about terminals or rendering. It maps a document path to a set of letters and their source lines.

3. Units

src/marks.rs newpersistence

Defines what a mark is and how it is found again in a document's source, and stores marks in a single TOML file.

Collaborators: dirs::data_dir, toml, serde, std::fs. No knowledge of ViewerState; capture and resolve are pure functions of the source text.

Mark::capture(source: &str, source_line: usize) -> Mark
Builds a mark from source line source_line. The fingerprint is that line's trimmed text, cut to FINGERPRINT_MAX_CHARS (120) on a char boundary. If the line is out of range, the fingerprint is empty.
Mark::resolve(&self, source: &str) -> MarkTarget
Finds the marked line in the current source. Unchanged(source_line) if the stored line still matches, or if the fingerprint is empty. Otherwise Moved(n) for the nearest matching line anywhere in the file; on a tie, the line above wins. NotFound(source_line) if no line matches. Lines are compared by their trimmed, capped text, and str::lines() indexing matches the renderer's line_starts.
MarkTarget::source_line(self) -> usize
The line to scroll to, whichever variant.
MarkStore::open() -> Self
Resolves data_dir()/mdterm/marks.toml. If there is no data dir, the store has no file and every save is a no-op.
MarkStore::at(file: PathBuf) -> Self
Store backed by an explicit file. Used by tests.
MarkStore::load(&self, doc: &Path) -> FileMarks
Marks for one document. If the file is missing or unreadable, or the document has no entry, returns empty marks. Never fails.
MarkStore::save(&self, doc: &Path, marks: &FileMarks) -> io::Result<()>
Re-reads the file, replaces this document's entry and writes atomically (tmp + rename, creating the dir). Returns InvalidData without writing if the existing file does not parse.
FileMarks::get(&self, letter: char) -> Option<&Mark>
The mark for a letter, if set. Returns a reference, because Mark now owns a String and is no longer Copy.
FileMarks::set(&mut self, letter: char, mark: Mark)
Inserts the mark, replacing any previous one for that letter.

src/viewer.rs - ViewerState and key handling modifiedTUI

Holds the current document's marks, handles the two-key sequence, and converts between viewport offset and source line.

Collaborators: marks::MarkStore (injected through ViewerOptions), marks::FileMarks, existing nav_history and set_toast.

fn current_doc_path(&self) -> Option<PathBuf>
Canonical path of files[current_file_idx]. None for stdin, or if the path cannot be canonicalized.
fn source_line_at(&self, offset: usize) -> Option<usize>
The first Some(source_line) at or after offset in wrapped. None when there is none (JSON).
fn offset_for_source_line(&self, source_line: usize) -> usize
Index of the first wrapped line whose source line is >= source_line, clamped to max_offset(). If the file got shorter, returns max_offset().
fn set_mark(&mut self, letter: char)
Captures a mark (Mark::capture(&self.content, line)) for the top of the viewport, stores it, saves, and shows a toast for the outcome.
fn jump_to_mark(&mut self, letter: char)
Resolves the mark against self.content. If the line moved, the stored line is updated and saved. Then it pushes the current position onto nav_history, scrolls, and shows a toast for the outcome. If the letter is unset, it only shows a toast.
fn save_marks(&self) -> io::Result<()>
Calls current_doc_path() then mark_store.save(..). Returns Ok(()) when there is no document path (stdin). Shared by set_mark and jump_to_mark.
fn handle_mark_key(state: &mut ViewerState, code: KeyCode)
Free fn, like handle_toc. Takes pending_mark: a-z dispatches to set_mark or jump_to_mark; any other key cancels.

5. Call chains

call return error path

5.1 Set a mark: m then a

  1. run loop -> handle_event(state, Key('m')): bool
  2. handle_event -> handle_normal(state, Char('m'), mods): bool - sets pending_mark = Some(MarkAction::Set); the status bar shows the pending hint on the next frame
  3. run loop -> handle_event(state, Key('a')): bool - intercept: pending_mark.is_some()
  4. handle_event -> handle_mark_key(state, Char('a'))
  5. handle_mark_key -> ViewerState::set_mark(&mut self, 'a')
  6. set_mark -> ViewerState::source_line_at(&self, self.offset): Option<usize> - Some(141)
  7. set_mark -> Mark::capture(&self.content, 141): Mark - fingerprint "## Ownership rules"
  8. set_mark -> FileMarks::set(&mut self, 'a', mark)
  9. set_mark -> ViewerState::save_marks(&self): io::Result<()>
  10. save_marks -> ViewerState::current_doc_path(&self): Option<PathBuf>
  11. save_marks -> MarkStore::save(&self, &doc, &self.marks): io::Result<()> - read, replace entry, write tmp, rename
  12. set_mark -> ViewerState::set_toast("Mark 'a' set")
  13. E1 source_line_at returns None (no source lines, e.g. an empty doc) -> set_toast("Nothing to mark here"); marks unchanged
  14. E2 current_doc_path returns None (stdin) -> save_marks returns Ok without writing; toast "Mark 'a' set" (session only)
  15. E3 save returns Err(e) (permissions, disk full, corrupt file) -> mark stays in memory; set_toast(format!("Mark 'a' set, not saved: {e}"))
  16. E4 second key is not a-z (Esc, digit, F1, ?) -> handle_mark_key clears pending_mark and does nothing; no toast, and the app does not quit
  17. E5 m in JSON view -> handle_normal shows set_toast("Marks are not available for JSON") and leaves pending_mark unset

5.2 Jump to a mark: ' then a

  1. run loop -> handle_event(state, Key('\'')) -> handle_normal(..) - sets pending_mark = Some(MarkAction::Jump)
  2. run loop -> handle_event(state, Key('a')) -> handle_mark_key(state, Char('a'))
  3. handle_mark_key -> ViewerState::jump_to_mark(&mut self, 'a')
  4. jump_to_mark -> FileMarks::get(&self, 'a'): Option<&Mark> - Some(Mark { source_line: 141, fingerprint: "## Ownership rules" })
  5. jump_to_mark -> Mark::resolve(&self, &self.content): MarkTarget - Unchanged(141), or Moved(146) when 5 lines were added above
  6. on Moved(n): jump_to_mark -> FileMarks::set(&mut self, 'a', Mark { source_line: n, fingerprint }) -> ViewerState::save_marks(&self): io::Result<()> - so the next jump starts from the corrected line
  7. jump_to_mark -> ViewerState::offset_for_source_line(&self, target.source_line()): usize
  8. jump_to_mark -> nav_history.push((current_file_idx, offset)) - so Backspace returns
  9. jump_to_mark: self.offset = target; set_toast("Jumped to mark 'a'")
  10. E1 get returns None -> set_toast("Mark 'a' not set"); no scroll and no history entry
  11. E2 resolve returns NotFound(line) (the marked line's text was edited or removed) -> jump to the stored line; the mark is not rewritten; set_toast("Mark 'a': text changed, jumped to saved line")
  12. E3 save after Moved fails -> the jump still happens and the in-memory mark is updated; set_toast(format!("Jumped to mark 'a', not saved: {e}"))
  13. E4 stored line is past the end of the file and NotFound -> offset_for_source_line returns max_offset(); the jump lands at the end
  14. E5 second key is not a-z, including A-Z -> cancel silently (same as 5.1 E4)

5.3 Load marks: startup and file switch

  1. main -> MarkStore::open(): MarkStore
  2. main -> viewer::run(ViewerOptions { mark_store, .. }): io::Result<()>
  3. run -> ViewerState::new(opts, cols, rows): ViewerState
  4. new -> current_doc_path() then MarkStore::load(&self, &doc): FileMarks
  5. later: handle_normal (Tab, BackTab, Backspace) or dispatch_link -> ViewerState::switch_file(idx): bool
  6. switch_file -> current_doc_path() then MarkStore::load(&self, &doc): FileMarks - replaces self.marks; also clears pending_mark
  7. E1 no data dir -> open() returns a store with no file; load returns empty and save is a no-op Ok
  8. E2 marks.toml missing or unparsable -> load returns empty FileMarks, silently, like Config::load
  9. E3 stdin -> current_doc_path is None -> marks = FileMarks::default()

5.4 Stamp source lines during render

  1. ViewerState::rebuild -> markdown::render_with(content, cw, theme, line_numbers, res): (Vec<Line>, DocumentInfo)
  2. render_with -> Renderer::new(..) - builds line_starts
  3. loop over (event, range): render_with -> Renderer::process(event, range.clone())
  4. for a code block: process(End(CodeBlock)) -> emit_code_block() - pre-stamps code rows with code_block_first_line + line_num
  5. render_with -> Renderer::stamp_new_lines(range.start) -> source_line_of(range.start): usize
  6. render_with: final flush_line() then stamp_new_lines(last_start)
  7. rebuild -> style::wrap_lines(&lines, cw): Vec<Line> - every wrapped piece keeps source_line
  8. rebuild -> ViewerState::finalize_layout() - expanded image rows copy source_line
  9. No error path: stamping cannot fail. Popped lines are handled by clamping stamped.

7. Test seams

  • marks.rs - Mark (unit, pure, no disk): capture trims and caps at 120 chars on a char boundary (multibyte text); resolve returns Unchanged when nothing changed; Moved after lines are inserted or deleted above; with duplicate text it picks the nearest match, and the line above on a tie; NotFound when the marked line was edited; an empty fingerprint is always Unchanged; CRLF sources behave like LF.
  • marks.rs - MarkStore (unit, MarkStore::at(tempdir)): save/load round-trip including char keys and fingerprints; saving doc A keeps doc B's entry; a missing parent dir gets created; a corrupt file loads empty, save returns InvalidData, and the file is left byte-for-byte unchanged; a store with no file saves Ok.
  • markdown.rs (unit, real renderer): a fixture with heading, paragraph, list, fenced code and table asserts source_line for each; code rows are per-line; no line is left None.
  • style.rs (unit): wrap_lines copies source_line to every piece, in both the plain and blockquote branches.
  • viewer.rs (unit, make_state_with_lines + temp store): source_line_at / offset_for_source_line incl. clamping; handle_event sequences ma, scroll, 'a; mEsc does not quit; m? does not open help; an unset mark gives a toast; JSON gives a toast; M toggles mouse_captured; mA sets nothing; after editing state.content above the mark, a jump lands on the moved line and the store holds the new line. The existing help_sections_no_duplicate_keys test covers the help edits.
  • E2E (scripted tmux): open test.md at 120 cols, scroll, ma, quit; reopen at 60 cols, 'a; capture the pane and assert the same heading or text is at the top. Then insert lines near the top of a copy of the file, reopen, 'a, and assert the same text is still at the top.

8. Assumptions

  1. The marked position is the top line of the viewport (offset), and jumping puts that line back at the top.
  2. Marks are stored per block for paragraphs, list items and tables, and per line inside code blocks. A mark inside a long wrapped paragraph returns to the paragraph's start.
  3. Valid letters are a-z, per file. A-Z are reserved and cancel like any other invalid key (decided).
  4. Setting an existing letter overwrites it without asking.
  5. After m or ', any key other than a-z cancels silently; Ctrl-c still quits.
  6. Jumping pushes onto the existing Backspace history; there is no separate '' "jump back".
  7. Marks do nothing in slide mode. In JSON view, m shows the toast "Marks are not available for JSON".
  8. Marks are saved on every set, not on quit, so a crash loses nothing.
  9. Documents are identified by canonical path. Moving or renaming a file loses its marks; symlinks resolve to the target.
  10. stdin documents get marks for the session only.
  11. When two mdterm instances save marks for the same document, the last save wins for that document; other documents are unaffected.
  12. Entries for deleted files are never pruned (the file stays tiny).
  13. Re-anchoring needs an exact match of the marked line's trimmed text. Inserting or deleting lines anywhere is handled. If the marked line itself is reworded, the mark falls back to its stored line with a toast; there is no fuzzy matching.
  14. The search covers the whole file, and the nearest match to the stored line wins, so a duplicated line (e.g. a repeated - [ ] todo) resolves to the copy closest to where the mark was.
  15. A re-anchored line is written back on jump. A NotFound mark is left unchanged, so it can still re-anchor if the text comes back.
  16. Re-anchoring happens only on jump, not on file load or live reload. A mark on a blank source line (an empty code row) has an empty fingerprint and never moves.
  17. There is no marks list overlay or delete-mark command in this change.
  18. The marks file stores 0-based source_line, the same index used internally.
