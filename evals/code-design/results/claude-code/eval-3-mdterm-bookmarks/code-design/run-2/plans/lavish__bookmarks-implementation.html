mdterm bookmarks - implementation design

Approach B: source-anchored marks. Signatures only, no bodies.

1. Decision2. Structure3. Units4. Data5. Call chains6. Conventions7. Test seams8. Assumptions9. Review decisions

1. Decision recap

Each rendered Line carries the source line it came from. A mark stores that source line, so it means the same thing at any width and across sessions. A new marks.rs owns the per-file mark set and persists it as JSON in the user data directory.

  • Decided in phase 2: approach B (source-anchored marks).
  • Decided in phase 2: mouse capture moves from m to M. m+letter sets a mark, '+letter jumps.
  • Decided in review: marks are a-z only, per file; stale entries for missing files are kept in v1.

3. Units

marks.rs

src/marks.rsnewpersistence layer, peer of config.rs

Owns the set of marks per document and persists file-backed ones to disk.

Collaborators
dirs::data_dir, serde_json, std::fs. No knowledge of the viewer or rendering.
  • MarkStore::load() -> Self - load_from(marks_path()). Never fails: missing or unreadable file gives an empty store, like Config::load.
  • MarkStore::load_from(path: Option<PathBuf>) -> Self - loads from an explicit file. None means "never persist" (no data dir, and tests).
  • get(&self, target, letter) -> Option<usize> - the source line stored for letter in target, from memory.
  • set(&mut self, target, letter, source_line) -> io::Result<()> - updates memory first, then, for File targets with a path, re-reads the file, merges this one entry and writes it atomically. Returns Err on read/parse/write failure; memory keeps the mark either way. Stdin and path: None return Ok(()) without I/O.
  • is_mark_letter(c) -> bool - true for ASCII lowercase a-z only (decided in review). Uppercase and other keys cancel the pending mark.
  • marks_path() -> Option<PathBuf> - dirs::data_dir()/mdterm/marks.json.
  • read_marks_file(path) -> io::Result<MarksFile> - NotFound gives Ok(MarksFile::default()). Bad JSON or an unknown version gives Err(InvalidData), so an unreadable file is never overwritten.
  • write_marks_file(path, file) -> io::Result<()> - create_dir_all, writes marks.json.tmp, then renames it over marks.json.
  • target_key(path) -> String - JSON map key for a canonical path (to_string_lossy).

style.rs - Line, wrap_lines

src/style.rsmodifieddata types and wrapping

Carries each line's source position through word-wrapping.

  • Line.source_line - new field. All 13 literals in style.rs set it.
  • wrap_lines - copies source_line onto every wrapped fragment, on both the blockquote path (src/style.rs:111) and the plain path (src/style.rs:126). This differs from meta, which only spreads to every fragment for clickable types. word_wrap itself is unchanged; it emits None and the caller fills it in.

markdown.rs - Renderer

src/markdown.rsmodifiedrendering

Stamps every line it emits with the source line of the block that produced it.

Collaborators
Byte ranges from parser.into_offset_iter() (src/markdown.rs:1585), already passed to process.
  • source_owner(&mut self, event, range) -> usize - for End events returns range.start, since the range covers the whole element. For all other events returns open_block_start, so lines flushed by a Start belong to the content before it. On Start it then records range.start as the new open_block_start.
  • stamp_new_lines(&mut self, owner_byte) - sets Some(source_line_of(owner_byte)) on lines[stamped_lines..] and advances stamped_lines.
  • source_line_of(&self, byte) -> usize - partition_point over source_line_starts.
  • Renderer::new - builds source_line_starts from source.
  • render_with - the loop becomes owner = source_owner(..), then process(..), then stamp_new_lines(owner). After the final flush_line() it stamps once more. None of the ~15 self.lines.push sites change beyond adding source_line: None to their literals.

json.rs

src/json.rsmodifiedrendering

Mechanical change only: its 20 Line { .. } literals add source_line: None. No behaviour change.

viewer.rs - ViewerOptions, ViewMode, ViewerState

src/viewer.rsmodifiedinteractive viewer

Holds the mark store and translates between the viewport and source lines.

Collaborators
crate::marks::{MarkStore, MarkTarget}, injected through ViewerOptions.
  • ViewerOptions.marks / ViewerState.marks - the store, moved in by ViewerState::new.
  • ViewMode::MarkPending(MarkAction) - one new variant instead of two, so the "pending" handling is shared. accepts_text_input is unchanged: ?/F1 during pending open help, which cancels the pending mark.
  • mark_target(&self) -> MarkTarget - Stdin if files is empty, otherwise File(canonicalize(files[current_file_idx])), falling back to std::path::absolute if canonicalize fails.
  • source_line_at_offset(&self) -> Option<usize> - source_line of the first non-blank row at or below offset. None if nothing below carries one (empty doc, JSON).
  • offset_for_source_line(&self, source_line) -> usize - first wrapped row whose source_line >= source_line, clamped to max_offset(). If none, returns max_offset().
  • finalize_layout (src/viewer.rs:639) - the rebuilt image rows copy source_line from the placeholder.

viewer.rs - mark key handlers

src/viewer.rsnew functionsmodified handle_event, handle_normal

Turns the m/' + letter key sequence into a set or jump.

  • handle_mark_pending(state, action, code) - always returns to Normal. A letter (is_mark_letter) dispatches to set_mark or jump_to_mark. Any other key cancels silently, including Esc, which does not quit here.
  • set_mark(state, letter) - JSON view: toast "Marks are not available for JSON". No source line: toast "Nothing to mark". Otherwise marks.set(..), then toast "Mark 'a' set", or "Mark 'a' set (not saved: <err>)" on Err.
  • jump_to_mark(state, letter) - JSON: same toast as above. Unset: toast "Mark 'a' not set". Otherwise pushes (current_file_idx, offset) to nav_history, sets offset = offset_for_source_line(..), toast "Mark 'a'".
  • Mark keys are not bound in slide mode: handle_slide_keys returns before the Normal match (src/viewer.rs:1610).

viewer.rs - status bar and help

src/viewer.rsmodifiedrendering of viewer chrome

Shows that a mark letter is expected, and documents the keys.

  • render_status_bar - new early branch, before the search-results branch (src/viewer.rs:2839) and in the same style: ╰─ m_ set mark · Esc cancel ──── pos ─╯, or ' _ jump to mark for Jump.
  • help_sections - Navigation gains ("m + letter", "Set mark at current position") and ("' + letter", "Jump to mark"). In Actions, ("m", ...) becomes ("M", "Toggle mouse capture (for text select)"). The existing duplicate-key test (src/viewer.rs:3976) covers the change.

main.rs

src/main.rsmodifiedentry point

Declares mod marks; and loads the store for the interactive viewer only.

README.md, CLAUDE.md

modifieddocs

README controls table: add the m/' mark rows and the M mouse-capture row, which was never documented. Also add a short note on where marks are stored. CLAUDE.md: "Ten source files" becomes eleven, plus a marks.rs bullet.

5. Call chains

call (solid) / return (dashed)error path

5.1 Startup: load marks

  1. main -> MarkStore::load(): MarkStore
  2. MarkStore::load -> marks_path(): Option<PathBuf>
  3. MarkStore::load -> MarkStore::load_from(path): MarkStore
  4. MarkStore::load_from -> read_marks_file(&path): io::Result<MarksFile>, which reads marks.json
  5. Error: no data dir, Err from read_marks_file (unreadable, bad JSON, unknown version) - load_from returns an empty store but keeps path. The user sees nothing; the next set re-reads, gets the same Err, and shows it in the toast.
  6. main -> viewer::run(ViewerOptions { marks, .. }) -> ViewerState::new(opts, ..) moves the store into state.marks

5.2 m + a: set a mark

  1. run -> handle_event(state, Key('m')) -> handle_normal(state, Char('m'), mods): bool sets state.mode = MarkPending(Set), returns false
  2. run -> render_frame -> render_status_bar(..) draws m_ set mark · Esc cancel
  3. run -> handle_event(state, Key('a')) -> handle_mark_pending(state, Set, Char('a')) sets mode = Normal
  4. handle_mark_pending -> is_mark_letter('a'): bool
  5. Error: not a letter (incl. Esc) - return. Pending is cancelled, no toast.
  6. handle_mark_pending -> set_mark(state, 'a')
  7. Error: state.json_view.is_some() - set_toast("Marks are not available for JSON"), return.
  8. set_mark -> ViewerState::source_line_at_offset(): Option<usize>
  9. Error: None - set_toast("Nothing to mark"), return.
  10. set_mark -> ViewerState::mark_target(): MarkTarget
  11. set_mark -> MarkStore::set(&target, 'a', line): io::Result<()>, updates files in memory
  12. MarkStore::set -> read_marks_file(&path): io::Result<MarksFile>, then merges the entry
  13. MarkStore::set -> write_marks_file(&path, &file): io::Result<()> (tmp + rename)
  14. Error: either I/O call returns Err(e) - set returns it, the mark stays in memory, and set_mark shows set_toast("Mark 'a' set (not saved: e)").
  15. set_mark -> set_toast("Mark 'a' set")

5.3 ' + a: jump to a mark

  1. run -> handle_event(state, Key('\'')) -> handle_normal(..) sets mode = MarkPending(Jump); the status bar draws '_ jump to mark
  2. run -> handle_event(state, Key('a')) -> handle_mark_pending(state, Jump, Char('a')) sets mode = Normal, then is_mark_letter (cancel as in 5.2)
  3. handle_mark_pending -> jump_to_mark(state, 'a')
  4. Error: JSON view - set_toast("Marks are not available for JSON"), return.
  5. jump_to_mark -> ViewerState::mark_target(): MarkTarget
  6. jump_to_mark -> MarkStore::get(&target, 'a'): Option<usize>
  7. Error: None - set_toast("Mark 'a' not set"), return.
  8. jump_to_mark -> ViewerState::offset_for_source_line(line): usize
  9. jump_to_mark pushes (current_file_idx, offset) onto nav_history, assigns state.offset, then set_toast("Mark 'a'")
  10. Backspace later pops nav_history (existing code, src/viewer.rs:1765) and returns to the previous position.

5.4 Rebuild: stamping source lines (startup, resize, reload, theme, l)

  1. ViewerState::rebuild -> markdown::render_with(content, cw, theme, line_numbers, res): (Vec<Line>, DocumentInfo)
  2. render_with -> Renderer::new(..) builds source_line_starts
  3. for each (event, range): render_with -> Renderer::source_owner(&event, &range): usize
  4. render_with -> Renderer::process(event, range) (unchanged; pushes lines)
  5. render_with -> Renderer::stamp_new_lines(owner) -> source_line_of(owner): usize
  6. after the loop: flush_line(), then stamp_new_lines(open_block_start)
  7. ViewerState::rebuild -> style::wrap_lines(&lines, cw): Vec<Line> copies source_line to every fragment
  8. ViewerState::rebuild -> finalize_layout() keeps source_line on resized image rows
  9. No error path: stamping cannot fail. JSON views go through json::render_* and get None everywhere.

7. Test seams

  • marks.rs - unit tests on MarkStore::load_from(Some(tmp)) with a unique path under std::env::temp_dir() (no new dev-dependency). Covers: round trip; set merges with entries another writer added; a corrupt file is left untouched and set returns Err but get still works; load_from(None) and Stdin never touch disk; char keys survive JSON.
  • markdown.rs - render_test asserts source_line on headings, paragraphs, code blocks, tables and consecutive list items (including items flushed by the next Start).
  • style.rs - wrap_lines copies source_line to every fragment on both the plain and blockquote paths.
  • viewer.rs - make_state_with_lines gets marks: MarkStore::load_from(None). Key-sequence tests via handle_event: ma, scroll, 'a restores the offset; mEsc does not quit; M toggles mouse; after a rebuild at a different width the mark lands on the same source line. The existing help tests cover the help table.
  • E2E - in tmux, cargo run -- test.md at 80 cols: set ma, quit; relaunch at 120 cols; 'a lands on the same heading; marks.json contains the entry.

8. Assumptions

  1. The marked position is the first non-blank row at the top of the viewport.
  2. Marks resolve to the start of a block (paragraph, heading, code block, list item, table). Inside a long paragraph, a jump lands on its first row.
  3. A jump puts the marked row at the top of the viewport, clamped near the end of the document.
  4. If edits moved the mark past the end of the file, the jump goes to the end.
  5. Setting a letter that is already set overwrites it silently; the toast is the same "Mark 'a' set".
  6. After m/', any non-letter key (including Esc) cancels without a toast. Esc does not quit while pending.
  7. The status bar shows a pending hint (m_ set mark · Esc cancel) until the letter arrives.
  8. Jumping pushes onto nav_history, so Backspace returns to where you were.
  9. Marks are not available in slide mode; the keys keep their slide meaning (none).
  10. In JSON view, both keys show "Marks are not available for JSON".
  11. Stdin content gets session-only marks.
  12. Files are keyed by canonical absolute path. Renaming or moving a file loses its marks; symlinks share marks with their target.
  13. Two running instances: set re-reads and merges, so neither loses the other's marks. Marks set elsewhere after startup are only seen after a restart.
  14. An unreadable or newer-version marks.json is never overwritten. Marks still work in-session, with a "not saved" toast.
  15. No data directory: marks work in-session only, silently.
  16. Entries for files that no longer exist are kept; no pruning in v1.
  17. Out of scope for v1: listing marks, deleting marks, ''/backtick jump-back, gutter indicators.
  18. Moving mouse capture to M is a breaking keybinding change. It is documented in README and help, with no compatibility alias.

9. Review decisions

  • Mark letters: a-z only, all per file. is_mark_letter accepts ASCII lowercase only; uppercase is left free for a possible future global-marks feature.
  • Stale entries: kept in v1. MarkStore never prunes paths that no longer exist.
