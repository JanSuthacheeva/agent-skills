Why marks need a source anchor

state.offset (src/viewer.rs:294) counts wrapped rows. The same source line lands on different rows whenever layout changes, so a stored row index points at the wrong text.

The renderer already gets byte ranges from parser.into_offset_iter() (src/markdown.rs:1585) and drops them. The plan keeps them.

Decision: how to track source lines and where the code lives

Option A - rejected

Minimal - parallel side tables

~200 prod lines, 5 files, Line untouched

  • render_with_src returns Vec<usize> next to lines, by watching lines.len() around each event
  • wrap_lines_with_origin returns pre-wrap index per row
  • ViewerState.line_src kept aligned by hand in finalize_layout
  • One marks.rs for store + format; glue inline in viewer.rs

Costs: three index-aligned arrays across every layout mutation, silent desync. Grows the 4356-line viewer.rs. Reload does not re-anchor marks; Backspace still drifts.

Option B - chosen

Clean - Line.src plus layered modules

4 new modules, ~50 mechanical literal edits, ~15 commits

  • Line.src: Option<SourceLine> travels with each row through wrap and image expansion
  • Pure domain (source_map, marks), IO (marks_store), glue (viewer/marks_ctl)
  • Reload re-anchors marks via prefix/suffix line diff
  • nav_history source-anchored, so Backspace is resize-safe too

Why: no way to desync, each layer unit-testable, sets a precedent for splitting viewer.rs. Line already derives Default (src/style.rs:55), so the field is cheap.

Trims applied to the full clean design

  • No flock advisory lock (would add unsafe libc FFI). Delta-update plus atomic rename already preserves other instances' marks outside a microsecond race.
  • No serde(flatten) unknown-field round-tripping; a version field is enough.
  • '' jump-back position is session-only, never persisted.

Source line tracking rules

Stamp from the first span

A nested Start(List) flushes the parent item while the current range already points at the child. Stamping when the first span is pushed gives the parent its own line.

Blank rows look forward

Separator rows take the line after the block, so a mark on a gap resolves forward instead of back into the previous block.

Code blocks are line-exact

Fence maps to the top border, code row i maps to fence + 1 + i. Indented blocks use start + i. Mermaid rows take the block start.

Paragraph granularity

A paragraph or table is one logical line. A mark set mid-paragraph jumps to the paragraph start. Accepted trade-off.

Set and jump

ma set

  • src = source_at(offset)
  • update in-memory set
  • store.update(key, |s| s.set(a, src))
  • refresh margin, toast Mark a set
  • store error: keep in memory, toast (not saved) once

'a jump

  • missing: toast Mark 'a' not set
  • record last_jump = source_at(offset)
  • push NavEntry
  • offset = resolve(line).min(max_offset)
  • toast Jumped to mark a

'' back

  • swap current position with last_jump
  • pushes NavEntry too
  • repeated presses toggle between two spots
  • none: toast No previous position

Persistence

Keyed by fs::canonicalize. Lines 0-based. Mark values are objects so a future text snippet for relocation fits without a version bump.

Behavior

  • Location: MDTERM_MARKS_PATH (tests / E2E), else state_dir(), else data_dir(), then mdterm/marks.json. Neither: session-only.
  • Write: create_dir_all, write marks.json.tmp.<pid>, sync_all, rename.
  • Concurrency: update re-reads disk and applies one mutation, so two instances do not clobber each other.
  • Prune: on load, in memory, only on NotFound (unmounted shares keep marks). Disk cleaned on the next write; read-only sessions never write.
  • Corrupt: load empty; next write moves the bad file to marks.json.corrupt.
  • Newer version: session-only, one-time toast, never overwrite.

Live reload and history

Re-anchor on reload

poll_file_changes computes LineRemap::between(old, new) before replacing content. Marks above an edit stay, marks below shift by the delta, marks inside a deleted region clamp to its start. Result is persisted.

Source-anchored history

nav_history becomes Vec<NavEntry { file_idx, src, offset }>. Restore prefers src via SourceIndex, falls back to offset. Fixes the existing resize drift on Backspace.
