Bookmarks: m + letter, ' + letter

Vim-style marks in the interactive viewer, saved per file between sessions. A mark stores the marked line's text plus its line number, so it keeps pointing at the right place after resizes and after small edits to the file.

Goal and agreed decisions

Keys

  • m a-z sets a mark at the top visible line
  • ' a-z jumps; Backspace returns
  • Mouse capture moves from m to M
  • No A-Z, no '', no backtick alias

Persistence

  • Platform state dir, never config.toml
  • Keyed by canonical absolute path
  • Saved immediately when a mark is set
  • Lost on rename / move (accepted)

Special cases

  • stdin: marks last only for the session
  • Slide mode: jump to the slide containing the mark
  • JSON viewer: disabled, toast explains
  • Past end of file: clamp to last line

How a mark stays on target

Each mark stores line (a 1-based hint) and text (that line's trimmed content). Resolving it against the current file:

  1. Exact: line line still reads text, so use it.
  2. Moved: otherwise pick the line with identical text closest to line (earlier line wins a tie).
  3. Edited: no line matches, so fall back to line, clamped to the end of the file.

When setting a mark, the anchor skips past blank lines to the next non-blank one, so anchors are real prose or code rather than empty lines.

Anchor options

Bare source line rejected

Survives resizes. Shifts by every line added or removed above the mark.

Heading + offset rejected

Survives edits in other sections. Doesn't work in files without headings, needs a two-step lookup, and breaks if the heading is renamed or edited above the mark in the same section.

Content + line hint chosen

Survives edits anywhere except on the marked line itself, and then falls back to the line number. Works with or without headings. One pure function that's easy to test.

Wrapped offset broken

What offset is today. Any resize breaks it.

Weak spot: lines like ---, a code fence or } appear many times. Picking the match nearest the stored line keeps the jump close.

Data flow

Architecture

1. Source line numbers on rendered lines style.rs, markdown.rs

  • Line gets source_line: Option<usize> (0-based). JSON and diagram lines leave it None.
  • wrap_lines / word_wrap copy it onto every wrapped piece, the same way meta is carried today.
  • Renderer computes line_starts once; line_of(byte) uses partition_point. Every block-level Start event (paragraph, heading, item, quote, table row, code block, math, rule, HTML) sets block_line.
  • A single push_line() fills in block_line and replaces every self.lines.push. emit_code_block numbers each content row fence + 1 + i, so marks inside long code blocks are exact.
  • About 40 Line { spans, meta } literals get ..Default::default() (Line already derives Default).
src/style.rs - Line gains a field

2. New module src/marks.rs

Holds the mark-matching logic and the persistence. No UI code goes here.

src/marks.rs - public surface (sketch)

Store

state_dir()/mdterm/marks.toml

dirs::state_dir(), falling back to ~/.local/state when it returns None. Entries whose key isn't a single a-z letter are ignored when loading.

Save on every set

Re-read the file, replace this file's entry, write marks.toml.tmp-<pid>, then rename it over the original. Two sessions on different files can't wipe each other's marks.

Corrupt store

Never overwritten. Marks still work for the session, and the toast says not saved, so data you might fix by hand isn't destroyed.

stdin / no home

FileMarks::session_only(): marks stay in memory, nothing is written.

3. Viewer viewer.rs

  • New state: pending_key: Option<PendingKey> (SetMark | JumpMark) and marks: FileMarks.
  • In handle_event, right after the Ctrl+C check and before the help toggle: if a key is pending, a-z (no Ctrl/Alt) runs set_mark / jump_to_mark and anything else cancels silently. This order makes mh set mark h instead of opening help.
  • In Normal mode, before handle_normal: m / ' start the pending key. One check covers both scroll mode and slide mode. In the JSON viewer it toasts instead.
  • set_mark: the top row is slide_boundaries[current_slide] in slide mode, otherwise offset. Takes the first source_line at or after that row, then Mark::capture and marks.set.
  • jump_to_mark: resolve, then the first wrapped row with source_line >= target. Scroll mode pushes nav_history and sets offset. Slide mode selects the last slide boundary at or before that row. No toast on success, same as [ / ].
  • Marks are loaded in ViewerState::new and in switch_file (which covers Tab, link following and Backspace). Reloading a file from disk needs no handling.

Risks and decisions

Risks

  • Line numbers are only accurate if every lines.push goes through push_line. A missed call site leaves None, so the mark lands on the next numbered line. The degradation is graceful and tests cover it.
  • marks.toml gains one entry per marked file and is never pruned. Fine at human scale.
Decided: state dir on macOS / Windows.
dirs::state_dir() returns None there, so marks fall back to ~/.local/state/mdterm/marks.toml. Accepted: on macOS config.toml stays under ~/Library/Application Support/mdterm/, so config and marks live in different trees.
