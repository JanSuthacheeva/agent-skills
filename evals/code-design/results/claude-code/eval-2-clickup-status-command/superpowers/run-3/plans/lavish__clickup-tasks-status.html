Plan bounded change Go / Cobra

clickup tasks status <id> <status>

Change a task's status from the terminal. The command checks the status against the task's own list before writing anything, and lists the valid statuses if the one you gave isn't valid.

Agreed behavior

change - exit 0 
clickup tasks status HGAI-1217 "In Progress"
HGAI-1217: open -> in progress
already set - exit 0 
clickup tasks status HGAI-1217 review
HGAI-1217 is already "review"
invalid - exit 1 
clickup tasks status HGAI-1217 done
Error: invalid status "done" for list "Sprint 12"
Valid statuses:
  to do
  in progress
  review
  complete
  • Matching: exact match, ignoring case and surrounding whitespace. ClickUp always gets the list's own spelling.
  • IDs: both custom (HGAI-1217) and native (86a3xyzw) IDs work, the same as clickup tasks <id>.
  • Output: plain text only, no -o json. Errors go to stderr through the existing Execute handler.

What happens when you run it

The flow takes three API calls. Every decision is made locally between the list fetch and the write, so ClickUp never sees an invalid status.

The task is checked against its home list (task.list), which is the list ClickUp takes statuses from, including for tasks that live in several lists. GET /list/{id} returns effective statuses, including ones inherited from the folder or space. E2E step 6 confirms this.

Design, by unit

1

API client bodies

internal/api/client.go

  • doRequest(method, path, query, payload any) marshals a non-nil payload to JSON and sets Content-Type only then.
  • New Put(path, query, payload); Get passes nil.
  • Debug lines go to stderr.
2

Shared custom ID query

internal/api/tasks.go

  • taskIDQuery(taskID, teamID) url.Values
  • Used by GetTask, GetTaskComments and UpdateTaskStatus.
3

List model + matching

pkg/models/list.go (new)

  • List{ID, Name, Statuses []Status}
  • FindStatus(name): strings.EqualFold after TrimSpace.
  • StatusNames() sorted by Orderindex.
  • Pure functions, so they can be tested without HTTP.
4

API methods

internal/api/lists.go (new), internal/api/tasks.go

  • GetList(listID) (*models.List, error)
  • UpdateTaskStatus(taskID, teamID, status) (*models.Task, error): PUT {"status": ...}, returns the updated task.
5

Command

internal/commands/tasks_status.go (new), registered with tasksCmd.AddCommand in its own init()

  • RunE is a thin wrapper. The logic lives in setTaskStatus, which depends on a small interface that the command package defines. *api.Client satisfies it, and tests pass a fake.
  • A custom Args validator replaces Cobra's accepts 2 arg(s), received 3 with a quoting hint for multi-word statuses.
  • Errors are wrapped like the rest of tasks.go: failed to get task / list / update task: %w.

Risks and edge cases

Statuses change between check and PUT. ClickUp rejects the PUT with a 400, which we show as failed to update task: .... No retry.
Inherited statuses. This depends on GET /list returning effective statuses. If the list comes back empty, we show a clear error instead of rejecting every status as invalid.
Name shadowing. A task whose ID is literally status can't be viewed with clickup tasks status. No real ClickUp ID looks like that.
Compatibility. The change only adds things. The doRequest signature is internal. Moving debug to stderr only affects anyone piping --debug output, and that output was already breaking JSON.
