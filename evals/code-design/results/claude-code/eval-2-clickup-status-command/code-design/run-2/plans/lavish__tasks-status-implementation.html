1. Decision recap

Approach A: a new tasks status Cobra subcommand fetches the task, then its list, and validates the requested status with a pure models.List.FindStatus helper before sending a PUT. The API layer only gains thin endpoint methods (GetList, UpdateTaskStatus) and a body-capable Put.

  • Decided in phase 2: validate up front in the command (A), not optimistic write (B) or an API-layer service (C).
  • Decided in phase 2: step 0 deletes the older duplicate DetailFormatter.FormatComments (internal/output/table.go:237-279) so the repo builds again.

2. Structure overview

Only tasks_status.go depends on models.List behaviour; the API layer just decodes into it. internal/output is not used by the new command - the table.go change is the unrelated build fix.

5. Call chains

5.1 clickup tasks status HGAI-1217 in progress - valid status

  1. Cobra -> runTasksStatus(cmd *cobra.Command, args []string): error - after cobra.MinimumNArgs(2) passes.
  2. runTasksStatus -> setTaskStatus(cmd.OutOrStdout(), args[0], strings.Join(args[1:], " ")): error
  3. setTaskStatus -> getAPIClient(): (*api.Client, error), then getConfig(): (*config.Config, error)
  4. setTaskStatus -> Client::GetTask(taskID, cfg.WorkspaceID): (*models.Task, error) -> Client::Get("/task/{id}", query)
  5. setTaskStatus -> Client::GetList(task.List.ID): (*models.List, error) -> Client::Get("/list/{id}", nil)
  6. setTaskStatus -> List::FindStatus(statusName): (models.Status, bool) -> (match, true)
  7. If strings.EqualFold(task.Status.Status, match.Status): fmt.Fprintf(w, "%s is already %q\n", ...), return nil - no PUT.
  8. setTaskStatus -> Client::UpdateTaskStatus(task.ID, cfg.WorkspaceID, match.Status): (*models.Task, error) -> Client::Put("/task/{id}", query, updateTaskRequest{Status: status}) -> doRequest(http.MethodPut, path, query, payload)
  9. setTaskStatus -> fmt.Fprintf(w, "%s: %s -> %s\n", task.GetDisplayID(), task.Status.Status, updated.Status.Status), return nil; exit 0.

Error paths (all returned from setTaskStatus, printed by Execute() as Error: ... on stderr, exit 1 - root.go:48-53):

  • Arg count < 2: Cobra returns requires at least 2 arg(s), only received 1 before RunE.
  • Config missing / unreadable: getAPIClient error returned unwrapped, as in getTask (tasks.go:101-104).
  • E1 step 4 fails (404 unknown ID, 401 token): fmt.Errorf("failed to get task: %w", err) wrapping *api.APIError.
  • E2 step 5 fails: fmt.Errorf("failed to get list statuses: %w", err).
  • E3 step 8 fails (e.g. statuses changed since step 5, permission denied): fmt.Errorf("failed to update task status: %w", err).

5.2 clickup tasks status HGAI-1217 done - status not in the list

  1. Steps 1-5 of 5.1.
  2. setTaskStatus -> List::FindStatus("done"): (models.Status{}, false)
  3. setTaskStatus -> invalidStatusError("done", task, list): error -> List::StatusNames(): []string; current status (task.Status.Status) is suffixed (current).
  4. setTaskStatus returns the error -> runTasksStatus -> Execute() prints it to stderr, os.Exit(1). No PUT is sent.
clickup tasks status HGAI-1217 done
Error: invalid status "done" for list "Sprint 12". Valid statuses:
  to do (current)
  in progress
  review
  complete

6. Conventions followed

  • Command registers itself in init() via AddCommand - mirrors tasks.go:41-42 (here on tasksCmd instead of rootCmd, the first subcommand).
  • xxxCmd var + runXxx RunE + lower-case worker func (setTaskStatus) - mirrors tasksCmd / runTasks / getTask (tasks.go:24,52,100).
  • Multi-call orchestration in the command, lazily obtaining client and config - mirrors getTask (tasks.go:100-124).
  • Errors wrapped as fmt.Errorf("failed to ...: %w", err) and surfaced by Execute() - tasks.go:113, root.go:48-53.
  • One Client method per endpoint, one file per domain, doc comment on every exported method, teamID for custom IDs - api/tasks.go:57-83, api/comments.go:11-33.
  • Response models with JSON tags in pkg/models, behaviour as methods on the model - models.Task.GetDisplayID (task.go:36).
  • Tests: table-ish t.Run subtests in the same package - pkg/models/task_test.go, internal/output/table_test.go.
  • Deviation: setTaskStatus takes an io.Writer (fed cmd.OutOrStdout()) instead of writing to os.Stdout like getTask (tasks.go:142). This lets the command test assert output without capturing stdout. Existing commands are not changed.
  • Deviation: addCustomTaskIDParams extracts a block that exists twice today (tasks.go:66-70, comments.go:17-20) because a third copy would be needed.

7. Test seams

  • pkg/models/list_test.go - unit: FindStatus exact / different case / surrounding spaces / unknown; StatusNames sorts by Orderindex. No fakes.
  • internal/api/client_test.go, tasks_test.go, lists_test.go (first api tests) - httptest.Server, set unexported c.baseURL; assert PUT method, path, custom-ID query, JSON body, decoded List statuses, *APIError on 4xx.

  • internal/output - existing tests compile and pass again after the duplicate is removed.
  • E2E: make build, then run bin/clickup tasks status against a scratch task in a real workspace with custom and native IDs, a valid, a wrong-case, a multi-word and an invalid status; confirm in the ClickUp UI.

8. Assumptions

  1. Status matching ignores case and surrounding whitespace; the list's own spelling is sent to ClickUp.
  2. Multi-word statuses work without quotes: args[1:] are joined with single spaces (quoted form also works).
  3. If the task is already in the requested status, print HGAI-1217 is already "in progress", send no PUT, exit 0.
  4. Success prints one line to stdout: HGAI-1217: to do -> in progress. No --output json for this command.
  5. Invalid status: exit 1, error on stderr listing valid statuses one per line in workflow order, current one marked (current). No "did you mean" suggestions.
  6. GET /list/{id} returns the effective statuses, including ones inherited from folder/space. Verified in E2E; if wrong, the design needs a fallback.
  7. The PUT uses the native task.ID from the fetched task, so custom-ID resolution happens once, in GetTask.
  8. Closed/done-type statuses are treated like any other; no confirmation prompt.
  9. Subtasks work the same way, using their own list.id.
  10. Help text, README, SKILL.md and the pre-built bin/ binaries are updated in the same change.

9. Decisions made during review

  • Multi-word statuses: trailing args are joined with single spaces (cobra.MinimumNArgs(2)); quoting also works.
  • Output: confirmation line only; no --output json flag on tasks status.
