1. Decision recap

Approach A: a new status subcommand under tasks chains three client calls (GET task, GET list, PUT task), mirroring how getTask chains calls. Validation is a pure method on a new models.List; the API client stays one-method-per-endpoint.

Decided in phase 2: approach A, because it matches getTask's orchestration and keeps the validation rule unit-testable without HTTP.

2. Structure overview

3. Units

tasksStatusCmd

newinternal/commands/tasks_status.gocommands

Responsibility: turn tasks status <id> <status> into a validated status change and report the outcome.

Collaborators: getAPIClient(), getConfig() (root.go), api.Client, models.List.

  • runTasksStatus - Cobra entry point; passes args[0], args[1] to changeTaskStatus.
  • changeTaskStatus - fetches task and list, validates, updates unless already in that status, prints the one-line result; returns a wrapped error on any failure.
  • invalidStatusError - builds the error naming the list and its valid statuses.

Client transport

modifiedinternal/api/client.goapi

Responsibility: perform authenticated HTTP requests against the ClickUp API.

  • doRequest gains body interface{}: when non-nil it is JSON-marshalled into the request body; marshal errors are returned. Debug mode also prints the request body.
  • Get - unchanged signature, now passes nil body.
  • Put (new) - PUT with JSON body; returns the raw response body or *APIError.

Task endpoints

modifiedinternal/api/tasks.goapi

Responsibility: map ClickUp task endpoints to models.Task.

  • UpdateTaskStatus (new) - PUT /task/{id} with {"status": status}; returns the updated *models.Task or *APIError.
  • addCustomTaskIDQuery (new, unexported) - sets custom_task_ids/team_id when the ID is custom. Replaces the duplicated block in GetTask (tasks.go:66-70) and GetTaskComments (comments.go:17-20), which both change to call it; behaviour unchanged.

List endpoints

newinternal/api/lists.goapi

Responsibility: map ClickUp list endpoints to models.List.

  • GetList - GET /list/{id}; returns *models.List including its statuses, or *APIError.

models.List

newpkg/models/list.gomodels

Responsibility: represent a ClickUp list and answer which statuses it allows.

  • FindStatus - case-insensitive exact match on Status.Status; returns the canonical Status and true, or zero value and false.
  • StatusNames - status names ordered by Orderindex, for the error message.

5. Call chain - clickup tasks status HGAI-1217 "in progress"

Happy path

  1. cobra -> runTasksStatus(cmd, ["HGAI-1217", "in progress"]): error -> changeTaskStatus("HGAI-1217", "in progress"): error
  2. changeTaskStatus -> getAPIClient(): (*api.Client, error)
  3. changeTaskStatus -> getConfig(): (*config.Config, error)
  4. changeTaskStatus -> Client.GetTask(taskID, cfg.WorkspaceID): (*models.Task, error)
  5. changeTaskStatus -> Client.GetList(task.List.ID): (*models.List, error) -> Client.Get("/list/{id}", nil)
  6. changeTaskStatus -> List.FindStatus(statusName): (models.Status, bool)
  7. If strings.EqualFold(task.Status.Status, target.Status): print HGAI-1217 is already "in progress", return nil (no PUT).
  8. changeTaskStatus -> Client.UpdateTaskStatus(taskID, cfg.WorkspaceID, target.Status): (*models.Task, error) -> Client.Put("/task/{id}", query, updateTaskRequest{Status: ...}): ([]byte, error) -> doRequest(http.MethodPut, ...)
  9. Print to stdout HGAI-1217: open -> in progress (task.GetDisplayID(), old task.Status.Status, new updated.Status.Status). Exit 0.

Error paths

All returned from changeTaskStatus; Execute() prints Error: ... to stderr and exits 1 (root.go:48-53).

  • E0 wrong arg count: cobra.ExactArgs(2) -> Error: accepts 2 arg(s), received 1
  • E1 no/invalid config: error from getAPIClient returned unchanged (existing message).
  • E2 task missing / no access: *APIError -> failed to get task: API error (status 404): ...
  • E3 list fetch fails: failed to get list statuses: %w
  • E4 FindStatus returns false -> invalidStatusError: 
    Error: status "doing" not found in list "Sprint 12"
Valid statuses: "open", "in progress", "review", "complete"
    No PUT is sent.
  • E5 PUT rejected (permissions, race with a status change): failed to update task status: %w

Deviations

  • First subcommand. tasksCmd takes a positional arg and now also a subcommand. Cobra matches subcommands by name on non-root commands, so clickup tasks HGAI-1217 keeps working; only a task ID literally named status would collide. File named tasks_status.go since existing files are one per top-level command.
  • Success output bypasses output.Formatter. The formatter interface is task/comment rendering; a confirmation line matches the existing --open message instead.
  • Small refactor (addCustomTaskIDQuery) beyond the feature, to avoid a third copy of the same block.

7. Test seams

  • models.List.FindStatus / StatusNames - table-driven unit tests in pkg/models/list_test.go: exact, different case, missing, empty list, ordering by Orderindex.
  • models.List JSON - deserialization test from a trimmed real GET /list response, like task_test.go:8.
  • api.Client (GetList, UpdateTaskStatus, Put) - first API tests: httptest.Server with baseURL set from an in-package test (client.go:20); assert method, path, custom ID query, JSON body.
  • tasksStatusCmd - no unit seam (package globals); verified E2E against a real workspace: valid, wrong case, invalid, same status, custom ID, native ID.

8. Assumptions

  1. GET /list/{id} returns the list's effective statuses even when they are inherited from the folder/space. First implementation step is an E2E check of this.
  2. The canonical status name from the list, not the user's casing, is what gets sent.
  3. Multi-word statuses must be quoted (cobra.ExactArgs(2)). Accepting unquoted words later is backwards compatible.
  4. Valid statuses in the error are listed in board order (Orderindex), quoted, comma-separated, so they can be copy-pasted.
  5. Closed/done-type statuses are allowed like any other.
  6. Aliases come free from the parent: clickup t status ..., clickup task status ....
  7. --debug also prints the PUT request body.
  8. The pkg/models/task.go Status type is reused as-is for list statuses.

9. Decisions made in review

  • Success output: one line HGAI-1217: open -> in progress; no -o flag on tasks status.
  • Already in requested status: skip the PUT, print HGAI-1217 is already "in progress", exit 0.
  • Matching: full status name only, case-insensitive; no prefix matching.
