1. Decision recap

Approach A: a new tasks status subcommand handles the whole flow itself, the same way getTask does (get task, get its list, match, update, print). The one real rule - is this a status of the task's list - is a pure method on a new models.List.

  • Decided in phase 2: no service layer, because no more write commands are planned; the command must stay in the same shape as getTask.
  • Prerequisite, separate commit: delete the duplicate DetailFormatter.FormatComments (internal/output/table.go:237-281) so main builds again. Keep the word-wrapping copy at :191.
clickup tasks status HGAI-1217 "In Progress"
HGAI-1217: to do -> in progress
clickup tasks status HGAI-1217 done
Error: "done" is not a status of list "Sprint 12". Valid statuses:
  to do
  in progress
  review
  complete
clickup tasks status HGAI-1217 "in progress"
HGAI-1217 is already "in progress"

3. Units

internal/commands/tasks_status.go

newcommand layer

Responsibility: the tasks status subcommand; runs the change-status flow and turns its outcomes into CLI output.

Collaborators: getAPIClient(), getConfig() (root.go), *api.Client, *models.List. Registers itself on tasksCmd in init().

  • runTasksStatus - Cobra RunE; joins args[1:] into the status name, so quotes are optional and calls changeTaskStatus.
  • changeTaskStatus - get task, get list, FindStatus, skip if unchanged, UpdateTaskStatus, print ID: old -> new. Returns a wrapped error on any failure.
  • invalidStatusError - builds the multi-line error naming the list and its valid statuses, in list order.

5. Call chain - clickup tasks status <id> <status>

One trigger. Solid arrows are calls, grey dashed arrows are returns, red dashed arrows are error exits back to Execute, which prints Error: %v and exits 1 (root.go:48-53).

  1. Cobra -> tasks_status::runTasksStatus(cmd, args): error
  2. runTasksStatus -> changeTaskStatus(args[0], strings.Join(args[1:], " ")): error (after getAPIClient(), getConfig())
  3. changeTaskStatus -> api.Client::GetTask(taskID, cfg.WorkspaceID): (*models.Task, error) -> GET /task/{id}
  4. GetTask fails (404, 401, network) -> return fmt.Errorf("failed to get task: %w", err) -> "Error: failed to get task: API error (status 404): ..."
  5. changeTaskStatus -> api.Client::GetList(task.List.ID): (*models.List, error) -> GET /list/{id}
  6. GetList fails -> return fmt.Errorf("failed to get statuses of list %q: %w", task.List.Name, err)
  7. changeTaskStatus -> models.List::FindStatus(statusName): (models.Status, bool)
  8. not found -> return invalidStatusError(statusName, list) -> "Error: \"done\" is not a status of list \"Sprint 12\". Valid statuses:" + one indented name per line; no PUT is sent
  9. strings.EqualFold(task.Status.Status, status.Status) -> fmt.Printf("%s is already %q\n", task.GetDisplayID(), status.Status); return nil (no PUT)
  10. changeTaskStatus -> api.Client::UpdateTaskStatus(taskID, cfg.WorkspaceID, status.Status): (*models.Task, error) -> Client::Put("/task/{id}", query, updateTaskStatusRequest): ([]byte, error)
  11. PUT fails (e.g. 403 no permission) -> return fmt.Errorf("failed to update task status: %w", err)
  12. changeTaskStatus -> fmt.Printf("%s: %s -> %s\n", updated.GetDisplayID(), task.Status.Status, updated.Status.Status); return nil

Wrong argument count is handled by Cobra (MinimumNArgs(2)): "Error: requires at least 2 arg(s), only received 1", before any call.

8. Assumptions

  1. Matching ignores case and surrounding whitespace; the list's own spelling is sent to ClickUp and printed.
  2. On a wrong status: exit 1, the list name in the message, valid statuses one per line in list order, no update sent.
  3. The valid statuses are whatever GET /list/{id} returns, which includes statuses inherited from the folder or space. This is checked in the E2E run.
  4. Setting the status the task already has sends no PUT, prints HGAI-1217 is already "in progress", and exits 0.
  5. Closed or done-type statuses (complete, closed) are allowed like any other; no confirmation prompt.
  6. No --output json on this subcommand; -o stays a local flag of tasks.
  7. Works with custom IDs, native IDs and the aliases task status / t status.
  8. A subtask is validated against its own list (task.List), not its parent's.
  9. A native task whose ID is literally status can no longer be viewed with clickup tasks status; accepted as practically impossible.
  10. Pre-built binaries in bin/ are rebuilt with make build-all, as the previous plan did.
  11. Duplicate FormatComments is fixed first in its own commit, keeping the word-wrapping version.

9. Decisions made in review

Approved
  • Success output: one line on stdout, HGAI-1217: to do -> in progress.
  • Multi-word statuses: no quotes needed. MinimumNArgs(2), and runTasksStatus joins args[1:] with a single space.
