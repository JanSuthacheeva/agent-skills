Code design - phase 3

clickup tasks status <id> <status>

Implementation design for approach A. It shows the shape of the code, with signatures but no function bodies.

1. Decision recap

A new tasks status Cobra subcommand runs the flow: get the task, get its list, match the status with List.FindStatus, then update. The API client gets thin endpoint methods (GetList, UpdateTaskStatus, Put). The matching rule lives on the models.

  • Approach A was chosen as recommended.
  • Everything after the task ID is joined into one status, so clickup tasks status HGAI-1217 in progress works without quotes.
  • Matching is exact, ignores case and surrounding whitespace, and does no prefix or fuzzy matching.
  • On success it prints one line, HGAI-1217: open -> in progress. With -o json it prints the updated task.
  • If the task already has that status, it prints a notice, makes no write and exits 0. The notice appears in every output mode. It goes to stderr, so with -o json stdout still holds only the task JSON.
  • Valid statuses are listed in the list's board order.
  • There is no confirmation prompt.

3. Units

internal/commands/tasks_status.go

newcommands

Responsibility: runs a status change for one task, from parsing args to printing the result.

Collaborators: getAPIClient() and getConfig() (root.go), *api.Client, *models.List, output.GetFormatter.

  • runTasksStatus: takes args[0] as the ID, joins and trims args[1:], rejects an empty status, then calls changeTaskStatus(cmd.OutOrStdout(), cmd.ErrOrStderr(), ...).
  • changeTaskStatus: gets the task and its list, then resolves the status. Depending on the result it returns the invalid-status error, prints the unchanged notice, or updates and prints the change. Fetch and update failures are wrapped with failed to ...: %w.
  • invalidStatusError: builds the error that names the bad status and lists the valid ones in board order.
  • printStatusChange: prints ID: from -> to, or the updated task as JSON with -o json.
  • printStatusUnchanged: always writes the "already in that status" notice to errOut. With -o json it also writes the current task to out.

internal/api/tasks.go

modifiedapi

Responsibility: wraps ClickUp's task endpoints.

  • UpdateTaskStatus: sends PUT /task/{id} with body {"status": ...} and returns the updated task from the response. API failures come back as *APIError.
  • addCustomTaskIDParams: adds custom_task_ids/team_id to the query. It replaces the inline checks in GetTask (:66-70) and GetTaskComments (comments.go:17-20), so the new method doesn't add a third copy.
  • Existing GetTask: its behaviour is unchanged. Only its query building uses the helper now.

internal/api/lists.go

newapi

Responsibility: wraps ClickUp's list endpoint.

  • GetList: sends GET /list/{id} and returns the list with its effective statuses, including statuses inherited from the folder or space. Failures come back as *APIError.

internal/api/client.go

modifiedapi

Responsibility: sends authenticated HTTP requests to ClickUp.

  • doRequest: gains a payload parameter. A non-nil payload is JSON-marshalled into the request body, and --debug prints it. Get passes nil, so GET behaviour is unchanged.
  • Put: performs a PUT with a JSON body and returns the raw response body.
  • SetBaseURL: points the client at another server so tests can use httptest. It mirrors SetDebug (:37).

pkg/models/list.go

newmodels

Responsibility: models a list's set of statuses and resolves typed names against it.

  • FindStatus: returns the first status where Matches(name) is true, or nil if none does.
  • OrderedStatuses: returns a copy of the statuses sorted by Orderindex, which is board order. The receiver is not mutated.

pkg/models/task.go - Status

modifiedmodels

Responsibility: the status value itself. It gains the one matching rule that both the validation and the "already in that status" check use.

  • Matches: compares names with strings.EqualFold after strings.TrimSpace on both sides.

6. Conventions followed

  • One file per command. The command is a package-level *cobra.Command with RunE: run* and is registered in init() (internal/commands/tasks.go:24-50, version.go).
  • Commands get dependencies through getAPIClient()/getConfig() (tasks.go:63-71, root.go:79-105).
  • Commands run multi-call flows. The parent-task fetch is the template (tasks.go:111-124).
  • Errors are wrapped with fmt.Errorf("failed to ...: %w", err) (tasks.go:85,113,149). Execute prints Error: ... and exits 1 (root.go:48-53).
  • Each API method maps to one endpoint: fmt.Sprintf path, c.Get, unmarshal into a model (api/tasks.go:59-83). Each resource gets its own file (comments.go, user.go).
  • Custom task ID query parameters (api/tasks.go:66-70, comments.go:17-20) move into one helper.
  • Domain helpers are methods on models (Task.GetDisplayID, pkg/models/task.go:36-52).
  • JSON output goes through output.GetFormatter(...).FormatTask (tasks.go:135-142). Plain confirmation lines use fmt (tasks.go:130).
  • The client has setter options (SetDebug, client.go:37), and SetBaseURL follows the same pattern.
  • Doc comments go on every exported and unexported declaration, in the existing style.
Deviations: (1) changeTaskStatus takes out, errOut io.Writer and is passed cmd.OutOrStdout()/cmd.ErrOrStderr(), where existing commands write to os.Stdout/os.Stderr directly (tasks.go:97,120,142). This lets the command be tested without capturing the process streams. The split itself follows the existing rule that notices go to stderr (tasks.go:120,128). (2) The status command has its own statusOutputFormat flag variable instead of reusing outputFormat, because the parent's flags are local (tasks.go:46) and are not inherited.

7. Test seams

  • pkg/models/list_test.go: table tests for Status.Matches (case, whitespace, "in" does not match "in progress"), FindStatus (hit and nil), and OrderedStatuses (sorts and leaves the receiver alone). Also decodes a GET /list JSON fixture. No fakes.
  • internal/api/tasks_test.go, lists_test.go: httptest.Server plus SetBaseURL. They check the method, path, custom-ID query parameters, the JSON body of the PUT, and that 4xx responses become *APIError. These are the first api tests.
  • internal/commands/tasks_status_test.go: a fake ClickUp httptest.Server, with the package globals cfg/apiClient set and reset per test. It calls changeTaskStatus with separate bytes.Buffers for out and errOut, for five cases: change, invalid (asserts no PUT and the message order), unchanged (no PUT, notice in errOut), unchanged with -o json (notice in errOut, valid JSON alone in out), and change with -o json.
  • E2E before committing: make run ARGS="tasks status <sandbox task> ..." against a real ClickUp list, covering all three outcomes and a custom ID.

8. Assumptions

  1. Valid statuses come from the task's home list (task.List.ID), even if the task also appears in other lists.
  2. The PUT sends the list's own spelling of the status (match.Status), not what the user typed.
  3. The "already in that status" notice always goes to stderr, like the existing warnings. With -o json, the current task also goes to stdout, so clickup tasks status ... -o json | jq still gets a task object.
  4. -o on status only switches on json. Any other value prints the one-line text, the same fallback as GetFormatter.
  5. The invalid-status error lists one status per line with two-space indentation, in board order. Statuses are shown as names only, without type or colour.
  6. Closed and done statuses are valid targets like any other, with no extra warning.
  7. --debug also prints the PUT request body.
  8. When the change is shipped, make build-all refreshes the pre-built binaries in bin/, as the last plan did.
